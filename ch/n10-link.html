Link layer and LANs

The link layer moves a datagram across one link, from one node to the physically adjacent node. This chapter covers how errors are detected (parity, checksum, CRC, with a full CRC division), how many nodes share one broadcast channel (TDMA, ALOHA, CSMA/CD, token passing), and how a switched Ethernet LAN works: MAC addresses, ARP, the Ethernet frame, self-learning switches and VLANs.

1Link-layer services

Terminology: hosts and routers are nodes; communication channels that connect adjacent nodes along the path are links (wired, wireless, LANs); the layer-2 packet is a frame, which encapsulates a datagram. A datagram may be transferred by different link protocols over different links (e.g. Wi-Fi on the first link, Ethernet on the next), and each link protocol provides different services. Analogy: a trip from Princeton to Lausanne goes by limo, plane and train; the tourist = datagram, each transport segment = communication link, the transportation mode = link-layer protocol, the travel agent = routing algorithm.

Where is it implemented? In each and every host, in a network interface card (NIC) or on a chip: an Ethernet or Wi-Fi card/chip implements the link and physical layers, attaches to the host's system buses, and is a combination of hardware, software and firmware. The sending side encapsulates the datagram in a frame and adds error-checking bits, reliable data transfer, flow control, etc.; the receiving side looks for errors, rdt, flow control, extracts the datagram and passes it to the upper layer.

2Error detection: parity and checksum

EDC = error detection and correction bits (e.g. redundancy); D = the data protected by error checking, which may include header fields. Error detection is not 100% reliable: the protocol may miss some errors, but rarely; a larger EDC field yields better detection and correction.

Single-bit parity

Detects single-bit errors. Even parity: set the parity bit so there is an even number of 1s. Example: data 0111000110101011 has nine 1s → parity bit 1. Any odd number of flipped bits is detected; an even number (2, 4…) is missed.

Two-dimensional parity

Arrange the bits in a matrix, add a parity bit for every row and every column. A single flipped bit breaks exactly one row parity and one column parity, so the receiver can detect and correct it (the intersection). Two-bit errors are detected but not corrected.

Internet checksum

Treat the contents as 16-bit integers, one's complement sum, complemented (see the worked example in N06). Cheap in software, used at the transport layer, weaker than CRC.

3Cyclic redundancy check (CRC)

A more powerful error-detection code. View the data bits D as a binary number. Choose an (r+1)-bit pattern, the generator G, known to both sides. Goal: choose r CRC bits R such that <D, R> (D followed by R) is exactly divisible by G (mod 2). The receiver knows G and divides <D, R> by G; a non-zero remainder means an error was detected. It can detect all burst errors of fewer than r+1 bits. Widely used in practice: Ethernet (CRC-32), 802.11 Wi-Fi.

Want:  D · 2^r  XOR  R  =  n · G     ⇔   R = remainder[ D · 2^r / G ]   (all arithmetic mod 2: + and − are XOR, no carries)

D = 101110, G = 1001 (r = 3)

Given

  • Append r = 3 zeros: 101110 000

Solution

  1. Long division with XOR (only when the leading bit is 1):
  2. 101110000 → 1011 ⊕ 1001 = 0010 → bring down → 0101 (leading 0, skip) → 1010 ⊕ 1001 = 0011 → 0110 (skip) → 1100 ⊕ 1001 = 0101 → 1010 ⊕ 1001 = 0011
  3. Remainder R = 011. Transmit 101110 011.
  4. Receiver: 101110011 ÷ 1001 → remainder 000 ✓. If a bit flips, the remainder is non-zero.
Exam trap

Check yourself with the "multiply back" rule: the transmitted word must divide by G with remainder 0. A common mistake is subtracting arithmetically (with borrows) instead of XOR.

4Multiple access protocols

Two types of links: point-to-point (point-to-point link between an Ethernet switch and a host, PPP for dial-up) and broadcast (shared wire or medium: old-style Ethernet, upstream HFC in cable-based access, 802.11 wireless LAN, 4G/5G, satellite). On a single shared broadcast channel, two or more simultaneous transmissions by nodes interfere: a collision if a node receives two or more signals at the same time.

A multiple access protocol is a distributed algorithm that determines how nodes share the channel, i.e. when a node can transmit. The communication about channel sharing must use the channel itself: no out-of-band channel for coordination. The ideal, for a broadcast channel of rate R bps: (1) when one node wants to transmit, it can send at rate R; (2) when M nodes want to transmit, each can send at average rate R/M; (3) fully decentralized: no special node to coordinate transmissions, no synchronization of clocks or slots; (4) simple.

5Slotted ALOHA and pure ALOHA

Slotted ALOHA assumptions: all frames the same size; time divided into equal slots (the time to transmit 1 frame); nodes start to transmit only at the beginning of a slot; nodes are synchronized; if 2 or more nodes transmit in a slot, all nodes detect the collision. Operation: when a node obtains a fresh frame, it transmits in the next slot. If no collision: the node can send a new frame in the next slot. If collision: the node retransmits the frame in each subsequent slot with probability p until success.

Efficiency of slotted ALOHA

Given

  • Efficiency: the long-run fraction of successful slots, with many nodes that all have many frames to send. N nodes, each transmits in a slot with probability p.

Solution

  1. P(a given node succeeds in a slot) = p(1−p)N−1
  2. P(any node succeeds) = Np(1−p)N−1
  3. Maximize over p: p* = 1/N; then N p*(1−p*)N−1 = (1 − 1/N)N−1 → 1/e ≈ 0.37 as N → ∞
  4. At best, the channel is used for useful transmissions 37% of the time!

Pure (unslotted) ALOHA: simpler, no synchronization; when a frame first arrives, transmit immediately. Collision probability increases with no synchronization: a frame sent at t0 collides with other frames sent in [t0−1, t0+1] (a vulnerable period of 2 frame times). P(success) = p·(1−p)2(N−1), maximized → 1/(2e) ≈ 0.18: even worse than slotted ALOHA. Pros of slotted ALOHA: a single active node can continuously transmit at the full rate; highly decentralized (only slots need to be synchronized); simple. Cons: collisions waste slots, idle slots, nodes may detect a collision in less than the time to transmit the packet, and clock synchronization.

6CSMA and CSMA/CD (Ethernet)

CSMA (carrier sense multiple access): simple CSMA: listen before transmit; if the channel is sensed idle, transmit the entire frame; if busy, defer. Human analogy: don't interrupt others! Collisions can still occur with carrier sensing: because of propagation delay, two nodes may not hear each other's just-started transmission. A collision wastes the entire packet transmission time; distance and propagation delay play a role in determining the collision probability.

CSMA/CD (collision detection): collisions are detected within a short time, and colliding transmissions are aborted, reducing channel wastage. Collision detection is easy in wired media (measure signal strengths, compare transmitted and received signals) and difficult with wireless (hence CSMA/CA in Wi-Fi).

Ethernet CSMA/CD algorithm
  1. The NIC receives a datagram from the network layer and creates a frame.
  2. If the NIC senses the channel: if idle, start frame transmission; if busy, wait until the channel is idle, then transmit.
  3. If the NIC transmits the entire frame without a collision, the NIC is done with the frame!
  4. If the NIC detects another transmission while sending: abort, and send a jam signal (48 bits) so all nodes know about the collision.
  5. After aborting, the NIC enters binary (exponential) backoff: after the m-th collision, the NIC chooses K at random from {0, 1, 2, …, 2m−1} and waits K·512 bit times, then returns to step 2. More collisions → a longer backoff interval (m is capped at 10; after 16 attempts it gives up).

CSMA/CD efficiency and minimum frame size

Given

  • tprop = max propagation delay between 2 nodes in the LAN; ttrans = time to transmit a max-size frame

Solution

  1. efficiency = 1 / (1 + 5·tprop/ttrans)
  2. Efficiency → 1 as tprop → 0 or as ttrans → ∞: better performance than ALOHA, and simple, cheap, decentralized.
  3. For collision detection to work, a sender must still be transmitting when the collision signal returns: ttrans ≥ 2·tprop. That is why Ethernet has a 64-byte minimum frame (512 bits = one backoff slot) and a maximum cable length.

7Taking-turns protocols; cable access

Polling

A centralized controller "invites" other nodes to transmit in turn; typically used with "dumb" devices (Bluetooth). Concerns: polling overhead, latency, and a single point of failure (the master).

Token passing

A control token message is explicitly passed from one node to the next, sequentially; only the token holder transmits. Concerns: token overhead, latency, single point of failure (the token).

Cable access network (DOCSIS)

Downstream: the CMTS broadcasts on FDM channels, a single sender, no multiple-access problem. Upstream: multiple cable modems share channels: TDM mini-slots assigned by MAP messages from the CMTS, and random access (binary backoff) in the request mini-slots. A mix of all three classes!

8MAC addresses and ARP

A 32-bit IP address is a network-layer address for an interface, used for layer-3 (network layer) forwarding, e.g. 128.119.40.136. A MAC (or LAN, physical, Ethernet) address is used "locally" to get a frame from one interface to another physically-connected interface (same subnet, in the IP-addressing sense). It is 48 bits, burned into the NIC ROM (sometimes software-settable), e.g. 1A-2F-BB-76-09-AD (hex notation, each "numeral" represents 4 bits). Each interface on the LAN has a unique 48-bit MAC address and a locally unique 32-bit IP address.

MAC address allocation is administered by the IEEE: a manufacturer buys a portion of the MAC address space (to assure uniqueness). Analogy: MAC address is like a Social Security Number, IP address is like a postal address. MAC is a flat address, so it is portable: you can move the interface from one LAN to another. IP is hierarchical and not portable: it depends on the IP subnet to which the node is attached.

ARP: Address Resolution Protocol

Question: how do you determine an interface's MAC address, knowing its IP address? Each IP node (host, router) on the LAN has an ARP table: IP/MAC address mappings for some LAN nodes, <IP address; MAC address; TTL>, where the TTL (time to live) is when the mapping will be forgotten (typically 20 min).

A wants to send a datagram to B on the same LAN; B's MAC is not in A's ARP table
  1. A broadcasts an ARP query containing B's IP address: destination MAC = FF-FF-FF-FF-FF-FF; all nodes on the LAN receive it.
  2. B replies to A with an ARP response giving its MAC address (unicast to A's MAC).
  3. A receives B's reply and adds the B entry to its local ARP table.
  4. ARP is "plug-and-play": nodes create their tables without intervention from the net administrator. It is also unauthenticated, which is exactly what ARP poisoning abuses.

Step by step
  1. A creates an IP datagram with source A, destination B, and a link-layer frame containing the A-to-B datagram with R's MAC as the destination address.
  2. The frame is sent from A to R; R receives it, removes the datagram, and passes it up to IP.
  3. R determines the outgoing interface and passes the datagram with source IP A, destination B to the link layer.
  4. R creates a frame containing the A-to-B IP datagram; the frame destination address is B's MAC address (found with ARP on subnet 2).
  5. B receives the frame, extracts the IP datagram (destination B), and passes it up the protocol stack to IP.
Remember

MAC addresses change at every hop; IP addresses do not (unless NAT). A never ARPs for B, because B is not on its subnet: it ARPs for its gateway.

10Ethernet

The "dominant" wired LAN technology: first widely used LAN technology, simpler and cheap, kept up with the speed race: 10 Mbps – 400 Gbps, a single chip, multiple speeds. Physical topology: bus (popular through the mid 90s: all nodes in the same collision domain, can collide with each other) → switched (prevails today: an active link-layer 2 switch in the center, each "spoke" runs a separate Ethernet protocol, so nodes do not collide with each other).

  • Unreliable: the receiving NIC doesn't send ACKs or NAKs to the sending NIC; data in dropped frames is recovered only if the initial sender uses higher-layer rdt (e.g. TCP), otherwise the dropped data is lost.

11Ethernet switches

A switch is a link-layer device that takes an active role: it stores and forwards Ethernet (or other) frames, examines the incoming frame's MAC address and selectively forwards the frame to one or more outgoing links; when the frame is to be forwarded on a segment, it uses CSMA/CD to access the segment. It is transparent: hosts are unaware of the presence of switches. It is plug-and-play, self-learning: switches do not need to be configured.

Multiple simultaneous transmissions: hosts have a dedicated, direct connection to the switch; switches buffer packets; the Ethernet protocol is used on each incoming link, so there are no collisions and links are full duplex. Each link is its own collision domain. Switching: A-to-A' and B-to-B' can transmit simultaneously, without collisions (but A-to-A' and C-to-A' cannot happen simultaneously).

Self-learning, filtering and forwarding
  1. When a frame is received at the switch: record the incoming link and the MAC address of the sending host in the switch table (MAC address, interface, TTL).
  2. Index the switch table using the MAC destination address.
  3. If an entry is found for the destination: if the destination is on the segment from which the frame arrived, drop the frame (filtering); else forward the frame on the interface indicated by the entry.
  4. Else (destination unknown) flood: forward on all interfaces except the arriving interface.

12VLANs: Virtual LANs

Motivation: Q: what happens as the LAN sizes scale, and users change their point of attachment? A single broadcast domain: scaling (all layer-2 broadcast traffic, ARP, DHCP, unknown MAC, must cross the entire LAN), efficiency, security and privacy issues. Administrative issue: a CS user moves office to EE, physically attached to the EE switch, but wants to remain logically attached to the CS switch.

A switch supporting VLAN capabilities can be configured to define multiple virtual LANs over a single physical LAN infrastructure. Port-based VLAN: switch ports grouped (by switch management software) so that a single physical switch operates as multiple virtual switches (e.g. ports 1–8 EE, ports 9–15 CS). Traffic isolation: frames to/from ports 1–8 can only reach ports 1–8. Dynamic membership: ports can be dynamically assigned among VLANs. Forwarding between VLANs is done via routing (just as with separate switches); in practice vendors sell combined switches plus routers.

VLANs spanning multiple switches: a trunk port carries frames between VLANs defined over multiple physical switches. Frames forwarded within a VLAN between switches can't be vanilla 802.1 frames (they must carry VLAN ID info), so the 802.1Q protocol adds/removes additional header fields for frames forwarded between trunk ports.

In practice

Data center networks connect tens to hundreds of thousands of servers with a hierarchy of top-of-rack switches, tier-2 and tier-1 switches and border routers, with many redundant paths between racks; load balancers spread requests; protocols like MPLS and ECMP spread traffic over the multiple paths. VLAN hopping attacks (double tagging, switch spoofing) are covered in the security course.

13Review

Compute the CRC for D = 1101, G = 101.

r = 2: divide 110100 by 101 (XOR) → remainder 10. Transmit 1101 10.

Max efficiency of slotted and pure ALOHA?

1/e ≈ 0.37 and 1/(2e) ≈ 0.18.

After the 3rd collision, from which set does an Ethernet NIC choose K?

{0, 1, …, 7} (23 − 1), and waits K·512 bit times.

Why does a host ARP for the router, not for the remote server?

ARP only works within the subnet; the frame only needs to reach the next hop, which is the gateway.

What does a switch do with a frame whose destination MAC is not in its table?

Floods it on all ports except the one it arrived on, and learns the source MAC.
