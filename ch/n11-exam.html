3Eight solved calculation patterns

Each pattern below is solved the way you should write it in the exam: given, formula, substitution with units, result. More patterns (Dijkstra, Bellman-Ford, CRC, ALOHA, cwnd traces) are worked in their chapters: N09, N10, N07.

1. End-to-end delay over several links

Given

  • Packet L = 1,500 B, 3 links of R = 2 Mbps, each 1,000 km (s = 2·108 m/s), 1 ms processing per router (2 routers), no queueing.

Solution

  1. dtrans per link = 12,000 / 2·106 = 6 ms; × 3 = 18 ms
  2. dprop per link = 106 / 2·108 = 5 ms; × 3 = 15 ms
  3. dproc = 2 × 1 = 2 ms → total 35 ms
  4. More: N02

2. Bandwidth-delay product and "how many bits on the wire"

Given

  • R = 10 Mbps, distance 20,000 km, s = 2.5·108 m/s.

Solution

  1. dprop = 2·107 / 2.5·108 = 0.08 s
  2. BDP = 107 × 0.08 = 800,000 bits; width of one bit = s / R = 25 m
  3. More: N02

3. HTTP response time with parallel / persistent connections

Given

  • Base HTML + 8 small objects, RTT0 = 100 ms, transmission time negligible.

Solution

  1. Non-persistent, serial: 2·RTT × 9 = 1,800 ms
  2. Non-persistent, 8 parallel: 2·RTT + 2·RTT = 400 ms
  3. Persistent, no pipelining: 2·RTT + 8·RTT = 1,000 ms; with pipelining: 2·RTT + 1·RTT = 300 ms
  4. More: N03

4. Client-server vs P2P distribution time

Given

  • F = 1 Gbit, N = 100, us = 100 Mbps, dmin = 10 Mbps, every peer u = 1 Mbps.

Solution

  1. C-S: max{100·109/108, 109/107} = max{1,000, 100} = 1,000 s
  2. P2P: max{10, 100, 1011/(108 + 108)} = max{10, 100, 500} = 500 s
  3. More: N05

5. Pipelining utilization and window size

Given

  • R = 1 Gbps, L = 8,000 bits, RTT = 30 ms.

Solution

  1. L/R = 8 µs; stop-and-wait U = 0.008 / 30.008 ≈ 0.027%
  2. Window of 3: U ≈ 0.08%. For U ≈ 1 the window must cover RTT + L/R: N ≥ 30.008 / 0.008 ≈ 3,751 packets
  3. More: N06

6. TCP timeout from RTT samples

Given

  • EstRTT = 100 ms, DevRTT = 5 ms, new SampleRTT = 120 ms, α = 0.125, β = 0.25.

Solution

  1. EstRTT = 0.875·100 + 0.125·120 = 102.5 ms
  2. DevRTT = 0.75·5 + 0.25·|120 − 102.5| = 3.75 + 4.375 = 8.125 ms (the textbook uses the new EstRTT; state which you use)
  3. Timeout = 102.5 + 4·8.125 = 135 ms
  4. More: N07

7. Subnetting with VLSM

Given

  • Block 200.1.1.0/24; need subnets of 100, 50 and 20 hosts.

Solution

  1. Largest first. 100 hosts → 128 (/25): 200.1.1.0/25 (hosts .1–.126, broadcast .127)
  2. 50 hosts → 64 (/26): 200.1.1.128/26 (.129–.190, broadcast .191)
  3. 20 hosts → 32 (/27): 200.1.1.192/27 (.193–.222, broadcast .223); .224/27 is left free
  4. More: N08

8. IPv4 fragmentation

Given

  • Datagram of 4,000 bytes (20 header + 3,980 data), MTU = 1,500.

Solution

  1. Data per fragment = 1,480 (divisible by 8 ✓)
  2. Fragment 1: length 1,500, offset 0, MF = 1. Fragment 2: length 1,500, offset 185, MF = 1. Fragment 3: 1,020 data → length 1,040, offset 370, MF = 0
  3. More: N08

4A day in the life of a web request

Our journey down the protocol stack is now complete. Putting it all together: a student attaches a laptop to the campus network and requests www.google.com. Every protocol from the course appears, in order.

Connecting to the Internet
  1. The arriving laptop needs its own IP address, the address of its first-hop router and of a DNS server: use DHCP.
  2. The DHCP request is encapsulated in UDP (port 67), encapsulated in IP (dst 255.255.255.255), encapsulated in 802.3 Ethernet (dst FF-FF-FF-FF-FF-FF).
  3. The Ethernet frame is broadcast on the LAN, received at the router running the DHCP server, and demuxed IP → UDP → DHCP.
  4. The DHCP server formulates a DHCP ACK with the client's IP address, the IP of the first-hop router and the name and IP of the DNS server; it is forwarded (switch learning) back to the client.
ARP, then DNS
  1. Before sending the HTTP request we need the IP of www.google.com: DNS. The DNS query is created, encapsulated in UDP, in IP, in Ethernet. To send the frame to the router we need the MAC of the router interface: ARP.
  2. An ARP query is broadcast, received by the router, which replies with an ARP reply giving the MAC of its interface. The client now knows the MAC of the first-hop router and can send the frame containing the DNS query.
  3. The IP datagram containing the DNS query is forwarded via the LAN switch from the client to the first-hop router, then from the campus network into the ISP network, routed (tables created by RIP, OSPF, IS-IS and/or BGP) to the DNS server.
  4. The DNS server demuxes to DNS and replies to the client with the IP address of www.google.com.
TCP, then HTTP
  1. To send the HTTP request, the client first opens a TCP socket to the web server: a TCP SYN segment (step 1 of the 3-way handshake) is inter-domain routed to the web server.
  2. The web server responds with TCP SYNACK (step 2); the client sends ACK (step 3): the TCP connection is established!
  3. The HTTP request is sent into the TCP socket; the IP datagram containing it is routed to www.google.com; the web server responds with an HTTP reply (containing the web page); the IP datagram containing the reply is routed back to the client.
  4. With HTTPS, a TLS handshake happens between TCP and HTTP (see security chapter 07).
Why

This sequence is the backbone of both courses: every attack in the security course targets one of these steps (DHCP starvation and rogue DHCP, ARP poisoning, DNS cache poisoning, TCP SYN flood and RST injection, TLS stripping). Learn it until you can draw it.

6Exam strategy

  1. Read every question once and mark the calculations: they are the most predictable points.
  2. For every calculation write: the formula, the values with units, the result with units. Partial credit lives in the first two lines.
  3. Draw a timeline (sender/receiver, time going down) for any question about RTT, handshakes, GBN/SR, or TCP loss recovery.
  4. For "explain why" questions, name the mechanism and the problem it solves (e.g. "the 3-way handshake prevents half-open connections from old duplicate SYNs").
  5. Multiple-choice: eliminate answers that mix layers (e.g. a switch routing by IP, ARP crossing a router).
  6. Keep 10 minutes to re-check units and the direction of inequalities (max vs min, ≤ vs <).
  7. Practice: the quiz below every chapter, and the mixed practice mode at Practice quiz.

7Final check

What are the four components of nodal delay, and which one depends on load?

Processing, queueing, transmission, propagation. Queueing depends on load (ρ).

Which transport protocol does DNS normally use, and why?

UDP port 53: a single short request and reply, no handshake cost. TCP for large responses and zone transfers.

After 3 duplicate ACKs, what does TCP Reno set cwnd and ssthresh to?

ssthresh = cwnd/2, cwnd = ssthresh + 3 MSS (fast recovery), then congestion avoidance.

How many usable host addresses in a /27?

25 − 2 = 30.

Which addresses change hop by hop: MAC, IP, or both?

MAC only (IP stays the same unless NAT rewrites it).
