Network layer: the control plane

The control plane decides the paths that the data plane follows. This chapter solves Dijkstra and Bellman-Ford by hand the way the exam asks, explains why the Internet uses OSPF inside an organization and BGP between organizations, and covers the protocols that keep the network observable: ICMP and SNMP, plus the SDN controller approach.

1Routing as a graph problem

Routing protocol goal: determine "good" paths (equivalently, routes) from sending hosts to the receiving host, through a network of routers. "Good" usually means least cost, fastest, or least congested. Abstraction: a graph G = (N, E) with N the routers and E the links; ca,b is the cost of the direct link between a and b (∞ if they are not direct neighbours). The cost is defined by the network operator: it could always be 1, or inversely related to bandwidth, or related to congestion.

ClassificationOptions
Global or decentralized information?Global: every router has the complete topology and link costs → link state algorithms. Decentralized: routers know only their neighbours and exchange information iteratively → distance vector algorithms.
Static or dynamic?Static: routes change slowly over time (configured). Dynamic: routes change more quickly, with periodic updates or in response to link cost changes.

2Link-state routing: Dijkstra's algorithm

Centralized: the network topology and link costs are known to all nodes, accomplished via "link state broadcast" (every node floods its link costs). Each node computes least-cost paths from itself ("source") to all other nodes, giving its forwarding table. Iterative: after k iterations, the least-cost paths to k destinations are known.

Notation:  D(v) = current estimate of least-cost-path cost from source to v
           p(v) = predecessor node along the path from source to v
           N'   = set of nodes whose least-cost path is definitively known

Initialization:  N' = {u};  for all v: D(v) = c(u,v) if v adjacent to u, else ∞
Loop:  find w not in N' with minimum D(w); add w to N'
       for each neighbour v of w not in N':  D(v) = min( D(v), D(w) + c(w,v) )
until all nodes are in N'

Ties (v and y both at 2 in step 2) can be broken arbitrarily. The resulting shortest-path tree from u gives the forwarding table: to reach v use link (u,v); for x, y, w and z use link (u,x), since all their paths go through x.

  • Oscillations are possible when link costs depend on traffic volume: all routers move traffic to the currently cheap path, which then becomes expensive, and so on.

3Distance-vector routing: Bellman-Ford

Based on the Bellman-Ford equation (dynamic programming). Let Dx(y) be the cost of the least-cost path from x to y. Then:

D_x(y) = min over neighbours v of x { c(x,v) + D_v(y) }

Key idea: from time to time, each node sends its own distance vector estimate to its neighbours. When x receives a new DV from any neighbour, it updates its own DV using the B-F equation. Under minor, natural conditions the estimate Dx(y) converges to the actual least cost dx(y). Each node: wait for (a change in local link cost or a message from a neighbour) → recompute the DV estimates → if the DV to any destination changed, notify the neighbours. The algorithm is iterative and asynchronous (each local iteration is caused by a local link cost change or a DV update message), distributed and self-stopping (each node notifies only when its DV changes).

One Bellman-Ford step

Given

  • Same graph as above. u's neighbours: v (cost 2), x (1), w (5). Their current estimates to z: Dv(z) = 5, Dx(z) = 3, Dw(z) = 3.

Solution

  1. Du(z) = min{ 2 + 5, 1 + 3, 5 + 3 } = min{7, 4, 8} = 4
  2. The neighbour that achieves the minimum (x) is the next hop in u's forwarding table for z.
  3. Matches the Dijkstra result (4 via x), as it must.

Three nodes, full iteration

Given

  • x–y 2, y–z 1, x–z 7. Each node starts knowing only its own links.

Solution

  1. t=0: x: [0, 2, 7], y: [2, 0, 1], z: [7, 1, 0] (columns x, y, z). Everyone sends its vector.
  2. t=1: x computes Dx(z) = min{c(x,y) + Dy(z), c(x,z) + Dz(z)} = min{2 + 1, 7 + 0} = 3 → x: [0, 2, 3]. Similarly z: Dz(x) = min{1 + 2, 7} = 3 → z: [3, 1, 0]. y is unchanged.
  3. t=2: x and z send their new vectors; nobody's vector changes → the algorithm stops (quiescent).

4Link cost changes: good news travels fast, bad news slowly

Nodes x, y, z with c(x,y) = 4, c(y,z) = 1, c(x,z) = 50. Initially Dy(x) = 4, Dz(x) = 5 (via y).

Cost decreases: 4 → 1

t0: y detects the change, sets Dy(x) = 1 and informs its neighbours. t1: z updates Dz(x) = 2 and sends its DV. t2: y receives it, nothing changes. Two iterations: "good news travels fast".

Cost increases: 4 → 60

y sees c(x,y) = 60 but z still claims Dz(x) = 5, so y computes Dy(x) = min{60, 1 + 5} = 6 (a path through z that actually goes back through y!). z then computes min{50, 1 + 6} = 7, y → 8, z → 9 … 44 iterations until z prefers its direct link of 50. This is the count-to-infinity problem; if the x–y link fails completely, it really counts toward ∞.

Remember

Poisoned reverse: if z routes through y to get to x, z tells y its distance to x is ∞ (so y won't route to x via z). It solves loops between two nodes but not loops involving three or more nodes. RIP also caps "infinity" at 16 hops.

6Making routing scalable: autonomous systems

Our study so far was idealized: all routers identical, a "flat" network. Not true in practice: scale (billions of destinations: you can't store all of them in routing tables, and the exchange would swamp the links) and administrative autonomy (the Internet is a network of networks; each administrator may want to control routing in its own network).

Routers are aggregated into regions called autonomous systems (AS), also known as "domains". Intra-AS (intra-domain) routing runs among routers within the same AS; all routers in the AS must run the same intra-domain protocol; a gateway router at the edge of its AS has links to routers in other ASes. Inter-AS (inter-domain) routing runs among ASes; gateways perform it (as well as intra-domain routing). The forwarding table is configured by both: intra-AS determines entries for destinations within the AS, inter-AS and intra-AS together for external destinations.

7OSPF: Open Shortest Path First

  • "Open": publicly available. Classic link-state: each router floods OSPF link-state advertisements (directly over IP rather than TCP/UDP, protocol 89) to all other routers in the entire AS; each router has the full topology and uses Dijkstra to compute its forwarding table.
  • Multiple link-cost metrics are possible: bandwidth, delay.
  • Security: all OSPF messages are authenticated (to prevent malicious intrusion).
  • Hierarchical OSPF: a two-level hierarchy, local area and backbone. Link-state advertisements are flooded only within an area or the backbone; each node has detailed area topology but only knows the direction to subnets in other areas. Area border routers "summarize" distances to destinations in their own area and advertise to the backbone; backbone routers run OSPF limited to the backbone; boundary routers connect to other ASes.

8BGP: Border Gateway Protocol, the glue that holds the Internet together

BGP provides each AS a means to: eBGP, obtain subnet reachability information from neighbouring ASes; iBGP, propagate reachability information to all AS-internal routers; and determine "good" routes to other networks based on reachability information and policy. It allows a subnet to advertise its existence, and the destinations it can reach, to the rest of the Internet: "I am here, here is who I can reach, and how". Two BGP routers ("peers") exchange BGP messages over a semi-permanent TCP connection (port 179).

BGP route selection (eliminate in order)
  1. Local preference value attribute: a policy decision.
  2. Shortest AS-PATH.
  3. Closest NEXT-HOP router: hot potato routing, choose the local gateway with the least intra-domain cost (get the packet out of your AS as fast as possible, don't worry about the inter-domain cost).
  4. Additional criteria.

Policy example: A, B, C are provider networks; x, w, y are customers. x is dual-homed (attached to B and C). Policy to enforce: x does not want to route from B to C via x, so x will not advertise to B a route to C. Similarly, B chooses not to advertise path BAw to C: B gets no "revenue" for routing CBAw, since none of C, A, w are B's customers. "Only carry traffic for your customers."

In practice

BGP has no built-in check that an AS really owns the prefix it announces. BGP hijacks (Pakistan Telecom taking YouTube offline in 2008) and route leaks still happen; RPKI signs which AS may originate which prefix. See security chapter 05.

9The SDN control plane

Why a logically centralized control plane? Easier network management (avoid router misconfigurations, greater flexibility of traffic flows), table-based forwarding allows "programming" routers, and an open, non-proprietary implementation of the control plane fosters innovation. Example of what is hard traditionally: an operator wants u-to-z traffic to flow along uvwz and x-to-z traffic along xwyz; with link-weight-based routing this requires re-defining link weights, and some splits are impossible.

ComponentRole
Data-plane switchesFast, simple, commodity switches implementing generalized forwarding (N08) in hardware; the flow table is computed and installed by the controller; protocol (OpenFlow) for communicating with the controller
SDN controller (network OS)Maintains network state information; interacts with the network-control applications "above" via a northbound API and with switches "below" via a southbound API (OpenFlow); implemented as a distributed system for performance, scalability, fault tolerance and robustness (e.g. ONOS, OpenDaylight)
Network-control appsThe "brains" of control: routing, access control, load balancing, implemented using the lower-level services the controller provides; can be from third parties

OpenFlow messages: controller-to-switch (features, configure, modify-state to add/delete/modify flow entries, packet-out to send a packet out of a specific port); switch-to-controller (packet-in: transfer a packet to the controller, flow-removed, port status). Example of the whole loop: S1 detects a link failure → sends port status to the controller → the controller updates its link-state info → Dijkstra (the routing app) recomputes → the controller installs new flow tables in the affected switches.

10ICMP: Internet Control Message Protocol

Used by hosts and routers to communicate network-level information: error reporting (unreachable host, network, port, protocol) and echo request/reply (used by ping). It is a network-layer protocol carried "above" IP: ICMP messages are carried in IP datagrams (protocol 1). An ICMP message has a type, a code, plus the first 8 bytes of the IP datagram causing the error (so the sender can match it to a connection).

Traceroute and ICMP in detail: the source sends sets of UDP segments to the destination (1st set TTL = 1, 2nd TTL = 2, …). The datagram in the n-th set arrives at the n-th router, which discards it and sends the source ICMP type 11 code 0 including the router's name and IP address. When the ICMP arrives, the source records the RTT. Stopping criterion: the UDP segment eventually arrives at the destination host, which returns ICMP "port unreachable" (type 3, code 3). 11Network management and SNMP

Autonomous systems have thousands of interacting hardware and software components. Network management covers monitoring, configuring and controlling them. Components: a managing server (the application, with network managers / humans in the loop), managed devices with manageable, configurable hardware and software components, each with data (configuration, operational, statistics), an agent on each device, and a network management protocol used by the server to query, configure and manage devices, and by devices to inform the server of data and events.

ApproachHow
CLIThe operator issues (types, scripts) commands directly on individual devices (e.g. via ssh)
SNMP / MIBThe operator queries/sets device data (the MIB, Management Information Base) using the Simple Network Management Protocol over UDP (agent port 161, traps to the manager on port 162). Two modes: request/response (GetRequest, GetNextRequest, GetBulkRequest, SetRequest → Response) and trap messages (the agent informs the manager of an exceptional event)
NETCONF / YANGA more abstract, network-wide, holistic approach: configuration management across many devices, with YANG as the data modelling language and NETCONF (over secure, reliable transport like SSH/TLS) for atomic, multi-device configuration changes
Remember

SNMPv1/v2c authenticate with a plaintext "community string" (often the default "public"), which is a classic reconnaissance target; SNMPv3 adds authentication and encryption. See security chapter 03.

12Review

In Dijkstra, which node is added to N' at each step?

The node not yet in N' with the smallest current D(·).

Write the Bellman-Ford equation.

Dx(y) = min over neighbours v of { c(x,v) + Dv(y) }.

Why does bad news travel slowly in DV?

Neighbours keep advertising stale low costs that route back through the node itself, so costs increase only one step per exchange (count-to-infinity).

Why use different protocols inside and between ASes?

Inside: one administrator, optimize performance (OSPF). Between: policy and scale dominate (BGP).

Which ICMP message ends a UDP traceroute?

Type 3 code 3, port unreachable, from the destination host.
