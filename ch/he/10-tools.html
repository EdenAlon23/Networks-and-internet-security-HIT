1כללי יסוד למעבדה

למה זה חשוב

סריקה או לכידת תעבורה ברשתות שאינן שלך או שאין לך אישור לבדוק היא עבירה בישראל (חוק המחשבים, 1995) וכמעט בכל מקום אחר. הסיבה שהמרצה מלמד את הכלים היא שתבין איך ה-packets נראים, כדי שתזהה אותם כמגן. בנה מעבדה: שתיים-שלוש מכונות וירטואליות ברשת host-only (למשל VirtualBox), ועל אחת מהן Wireshark.

2Wireshark ו-tcpdump: לראות את ה-packets

מטרה: ללכוד frames מממשק ולפענח כל header, שכבה אחרי שכבה. זה הכלי שעונה על השאלה של המרצה "לאן ה-packet הולך ואיזה header יש לו". כרטיס הרשת עובר ל-promiscuous mode, ה-kernel מעביר עותק של כל frame ל-libpcap, והכלי מפענח Ethernet ← IP ← TCP/UDP ← אפליקציה.

איך קוראים packet אחד ב-Wireshark
  1. החלון העליון: שורה לכל frame (זמן, מקור, יעד, פרוטוקול, מידע).
  2. החלון האמצעי: ה-headers כעץ. פותחים Ethernet II (dst MAC, src MAC, EtherType 0x0800), אחר כך Internet Protocol (TTL, ID, flags, offset, protocol 6/17/1), ואחר כך TCP (פורטים, seq, ack, דגלים, window).
  3. החלון התחתון: הבתים הגולמיים; לחיצה על שדה מדגישה את הבתים שלו.
  4. Statistics ← Conversations ו-Follow ← TCP Stream בונים מחדש זרימות שלמות; Statistics ← I/O Graph מראה הצפה כקפיצה בגרף.
זווית ההגנה

האזנה היא פסיבית ובלתי נראית על הקו. ההגנות הן רשתות עם switches ו-port security, אימות 802.1X, ומעל הכל הצפנה (TLS, SSH, WPA2/3) כך שה-payload שנלכד חסר ערך. לפעמים אפשר לזהות כרטיס ב-promiscuous mode ע"י שליחת frame ל-MAC שגוי עם IP נכון ובדיקה מי עונה.

4Shodan ו-Maltego: OSINT פסיבי

Shodan

מנוע חיפוש שסורק את כל מרחב ה-IPv4 ברציפות ושומר את ה-banners שחוזרים (headers של HTTP, גרסאות SSH, תעודות TLS, פרוטוקולים תעשייתיים). מחפשים במאגר שלו, ולכן אף packet שלך לא מגיע למטרה. פילטרים כמו org:"Example Ltd", port:3389, ssl.cert.subject.cn:example.com.
פלט: IP, פורט פתוח, banner, מוצר/גרסה, מיקום, לפעמים CVE ידועים.

Maltego

כלי גרפי: מתחילים מישות (דומיין, אדם, מייל, IP) ומריצים "transforms" ששואלים מקורות ציבוריים (DNS, whois, מנועי חיפוש, רשתות חברתיות) ומציירים את הקשרים. מראה את הקשרים: דומיין ← MX ← IP ← דומיינים אחרים על אותו IP ← כתובות מייל ← אנשים.
פלט: גרף שאפשר לייצא כדוח.

זווית ההגנה

אין מה לזהות, כי זה פסיבי. להריץ Shodan על הארגון שלך באופן קבוע (או להשתמש בשירות הניטור שלו) ולהסיר מה שלא צריך להיות ציבורי; לצמצם מידע על עובדים באתרים; לנטר certificate transparency כדי לראות כל תעודה שהונפקה לדומיינים שלך.

5netcat: TCP/UDP גולמי ביד

מטרה: "האולר השוויצרי של TCP/IP". פותח חיבור TCP או UDP ומחבר אותו למקלדת ולמסך, או מאזין בפורט. הקורס משתמש בו ל-banner grabbing: הרבה שירותים מכריזים על השם והגרסה שלהם ברגע שמתחברים.

nc -v 192.168.56.10 22          # connect; an SSH server sends its banner first
SSH-2.0-OpenSSH_8.9p1 Ubuntu-3

nc -v 192.168.56.10 80          # HTTP waits for us; type a request, then an empty line
HEAD / HTTP/1.0

HTTP/1.1 200 OK
Server: Apache/2.4.52 (Ubuntu)

nc -zv 192.168.56.10 20-25      # -z: only check if ports open, send no data
nc -l -p 4444                   # listen (on your own lab VM) to test a firewall rule

על הקו: לחיצת יד רגילה (SYN, SYN/ACK, ACK), ה-banner ב-segment המידע הראשון מהשרת, ואז FIN. בדיוק מה ש-nmap -sT עושה, רק ביד, פורט אחד בכל פעם.

זווית ההגנה

להסתיר או להכליל banners של גרסאות (ServerTokens Prod ב-Apache, server_tokens off ב-nginx), לשמור על תוכנה מעודכנת כך שגרסה שדלפה לא תועיל, ולהתריע על הרבה חיבורים קצרים שקוראים banner ונסגרים.

6nmap: גילוי, מצבי פורט, גרסאות

מטרה: לגלות מחשבים חיים, למצוא פורטים פתוחים, לזהות שירותים ומערכת הפעלה. סוגי הסריקה וה-packets המדויקים שלהם נמצאים בפרק 03 עם אנימציות; כאן כרטיס עזר של הפקודות מההרצאה.

איך קוראים את הפלט

open: שירות מאזין. closed: המחשב חי וענה RST, אין שירות. filtered: משהו זרק את הבדיקה, כלומר יש חוק firewall. שילוב של פורטים closed ו-filtered ממפה את מדיניות ה-firewall.

זווית ההגנה

לסגור שירותים שלא בשימוש, firewall עם default-deny (פרק 09) כך שרוב הפורטים יהיו "filtered", firewall עם מצב כך ש-ACK/FIN/Xmas נזרקים כ-INVALID, ו-IDS (Snort, בהמשך) שמתריע כשמקור אחד נוגע בהרבה פורטים. להגביל קצב ולרשום ללוג.

7hping: packet מפוברק אחד בכל פעם

מטרה: לבנות packet בודד של TCP, UDP או ICMP עם שדות header לבחירה ולהציג את התשובה, כמו ping אבל לכל פרוטוקול. בקורס הוא מדגים סוגי הודעות ICMP (למשל Information Request) ואיך מחשב עונה לצירופי דגלים מסוימים. זו הדרך הכי טובה לראות שדה header אחד משתנה ולעקוב אחרי התוצאה ב-Wireshark.

hping3 -S -p 80 -c 1 192.168.56.10     # one SYN to port 80 on your lab VM
#  reply: flags=SA → port open;  flags=RA → port closed
hping3 -1 -c 1 192.168.56.10           # ICMP echo (mode -1), like ping
hping3 -2 -p 53 -c 1 192.168.56.10     # one UDP packet to port 53
שדה בתשובהמשמעות
flags=SASYN/ACK: מאזין
flags=RARST/ACK: סגור
ttl=64 / 128TTL התחלתי טיפוסי ל-Linux / Windows (רמז למערכת ההפעלה)
id=…IP ID; אם הוא עולה ב-1 לכל packet, המחשב יכול לשמש zombie ל-idle scan (פרק 03)
win=…TCP window, עוד רמז למערכת ההפעלה
זווית ההגנה

סינון עם מצב זורק packets מפוברקים שלא שייכים לחיבור; IP ID אקראי (מערכות מודרניות) עוצר idle scans; לזרוק סוגי ICMP חריגים (Information/Timestamp/Address Mask requests) בקצה.

8Snort: מבט המגן

מטרה: IDS/IPS בקוד פתוח מבוסס חוקים (בדיקת חתימות, פרוטוקול ואנומליות). הוא יושב איפה שהוא יכול לראות תעבורה (span port או inline) ומעלה התראות. הרכיבים מההרצאה:

  1. Packet decoder: לוקח packets מהממשק ומפענח את ה-headers.
  2. Preprocessors: מנרמלים תעבורה: מרכיבים IP fragments וזרמי TCP, מזהים סריקות פורטים (sfPortscan). בגלל זה פיצול סריקה (‎-f בפרק 03) לא מסתיר אותה מ-Snort.
  3. Detection engine: החלק הכי חשוב; מפעיל את החוקים על כל packet.
  4. Logging and alerting: כותב התראות ו-packets לקבצים או למסד נתונים.
  5. Output modules: שולחים ל-syslog, למסד נתונים, ל-SIEM.
# action proto src_ip src_port -> dst_ip dst_port (options)
alert tcp any any -> $HOME_NET any (msg:"Xmas scan"; flags:FPU; sid:1000001; rev:1;)
alert tcp any any -> $HOME_NET any (msg:"NULL scan"; flags:0; sid:1000002; rev:1;)
alert icmp any any -> $HOME_NET any (msg:"ICMP to broadcast"; ip_proto:1; sid:1000003; rev:1;)
alert udp any 53 -> $HOME_NET any (msg:"Large DNS response"; dsize:>1400; sid:1000004; rev:1;)
למה חוקים על שדות header עובדים

כל option בחוק קורא שדה header מסוים: flags:FPU קורא את בית 13 ב-TCP header, dsize את אורך ה-payload, ttl, itype/icode את ה-ICMP header. לסריקות ולהצפות יש טביעות header (דגלים שאף לקוח אמיתי לא משתמש בהם, הרבה SYN בלי ACK), וזה בדיוק מה שפרקים 03 ו-05 לימדו.

עולם אמיתי

Snort 3 ו-Suricata הם הסטנדרטים בקוד פתוח; ההתראות שלהם נכנסות ל-SIEM. IDS רואה, IPS גם חוסם (inline). תעבורה מוצפנת מגבילה חוקים על ה-payload, ולכן חוקים על headers וזרימות חשובים יותר.

9ניטור ARP: arpwatch, XArp

ההרצאה מונה כלי תוכנה לזיהוי ARP poisoning: arpwatch, XArp, anti-arpspoof. הם מחזיקים טבלה של זוגות IP ↔ MAC שנראו ברשת ומתריעים כשזוג משתנה ("flip flop") או כש-MAC אחד טוען להרבה כתובות IP (למשל ה-IP של ה-gateway פתאום עונה מה-MAC של מחשב נייד).

sudo arpwatch -i eth0          # logs to syslog:
# "flip flop 192.168.56.1 08:00:27:11:11:11 (08:00:27:22:22:22)"
arp -a                         # your own ARP cache: check the gateway's MAC
ip neigh show
זווית ההגנה (פרק 04)

Dynamic ARP Inspection ב-switch (בודק ARP מול ה-bindings של DHCP snooping), רשומות ARP סטטיות למחשבים קריטיים, port security, והצפנה כך ש-MITM רואה רק ciphertext. ב-Wireshark, ה-display filter arp.duplicate-address-detected מסמן תשובות סותרות.

10openssl ו-gpg: לבדוק את פרקי ההצפנה ביד

openssl s_client -connect example.com:443 -servername example.com
#   prints the certificate chain (subject, issuer), the TLS version and cipher suite
openssl x509 -in cert.pem -noout -text      # every X.509 field from chapter 07
openssl dgst -sha256 file.iso               # a hash, compare to the published value
openssl rand -hex 16                        # 128 random bits, e.g. an AES key or IV

gpg --gen-key                               # PGP key pair (chapter 08)
gpg --fingerprint alice@example.com         # verify this out of band
gpg --verify file.tar.gz.sig file.tar.gz    # check a signature (H(m) + public key)
gpg -e -s -r bob@example.com msg.txt        # sign then encrypt, as in chapter 08
dig TXT _dmarc.example.com +short           # DMARC policy
על מה להסתכל

ב-s_client: "Verify return code: 0 (ok)" אומר שהשרשרת הגיעה ל-Root מהימן; שורת ה-cipher מראה ECDHE (forward secrecy) ו-AES-GCM (AEAD). ב-x509: תאריכי Validity, Subject Alternative Name, ו-Signature Algorithm (sha256WithRSAEncryption, לא md5/sha1).

האנימציה של הפרק מראה את הזרימה. הפלט של כל שלב הוא הקלט של הבא, ו-Wireshark רץ כל הזמן כדי שתראה כל בדיקה:
