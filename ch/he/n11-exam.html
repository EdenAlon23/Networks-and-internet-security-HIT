ערכת מבחן

כל מה שצריך בבוקר המבחן: כל הנוסחאות בטבלה אחת עם היחידות והפרק שממנו הן באות, שמונה תבניות החישוב שחוזרות שוב ושוב עם דוגמה פתורה לכל אחת, "יום בחייה של בקשת web" שמחבר את כל חמש השכבות, ואסטרטגיה למבחן עצמו.

3שמונה תבניות חישוב פתורות

כל תבנית כאן פתורה כמו שצריך לכתוב במבחן: נתון, נוסחה, הצבה עם יחידות, תוצאה. עוד תבניות (Dijkstra, ‏Bellman-Ford, ‏CRC, ‏ALOHA, מעקב cwnd) פתורות בפרקים שלהן: N09, N10, N07.

1. השהיה מקצה לקצה על כמה קווים

נתון

  • חבילה L = 1,500 B, ‏3 קווים של R = 2 Mbps, כל אחד 1,000 ק"מ (s = 2·108), ‏1 ms עיבוד בכל נתב (2 נתבים), בלי תור.

פתרון

  1. dtrans לקו = 12,000 / 2·106 = 6 ms; × 3 = 18 ms
  2. dprop לקו = 106 / 2·108 = 5 ms; × 3 = 15 ms
  3. dproc = 2 × 1 = 2 ms ← סה"כ 35 ms
  4. עוד: N02

2. מכפלת רוחב פס בהשהיה ו"כמה ביטים על הקו"

נתון

  • R = 10 Mbps, מרחק 20,000 ק"מ, s = 2.5·108.

פתרון

  1. dprop = 2·107 / 2.5·108 = 0.08 s
  2. BDP = 107 × 0.08 = 800,000 ביט; "רוחב" של ביט = s / R = 25 מ'
  3. עוד: N02

3. זמן תגובה ב-HTTP עם חיבורים מקבילים / קבועים

נתון

  • HTML בסיס + 8 אובייקטים קטנים, RTT0 = 100 ms, זמן שידור זניח.

פתרון

  1. Non-persistent טורי: 2·RTT × 9 = 1,800 ms
  2. Non-persistent, ‏8 במקביל: 2·RTT + 2·RTT = 400 ms
  3. Persistent בלי pipelining: ‏2·RTT + 8·RTT = 1,000 ms; עם pipelining: ‏2·RTT + 1·RTT = 300 ms
  4. עוד: N03

4. זמן הפצה שרת-לקוח מול P2P

נתון

  • F = 1 Gbit, ‏N = 100, ‏us = 100 Mbps, ‏dmin = 10 Mbps, לכל עמית u = 1 Mbps.

פתרון

  1. C-S: ‏max{100·109/108, 109/107} = max{1,000, 100} = 1,000 s
  2. P2P: ‏max{10, 100, 1011/(108 + 108)} = max{10, 100, 500} = 500 s
  3. עוד: N05

5. ניצולת ב-pipelining וגודל חלון

נתון

  • R = 1 Gbps, ‏L = 8,000 ביט, ‏RTT = 30 ms.

פתרון

  1. L/R = 8 µs; ‏stop-and-wait: ‏U = 0.008 / 30.008 ≈ 0.027%
  2. חלון של 3: ‏U ≈ 0.08%. כדי ש-U ≈ 1, החלון צריך לכסות RTT + L/R: ‏N ≥ 30.008 / 0.008 ≈ 3,751 חבילות
  3. עוד: N06

6. Timeout של TCP מדגימות RTT

נתון

  • EstRTT = 100 ms, ‏DevRTT = 5 ms, דגימה חדשה 120 ms, ‏α = 0.125, ‏β = 0.25.

פתרון

  1. EstRTT = 0.875·100 + 0.125·120 = 102.5 ms
  2. DevRTT = 0.75·5 + 0.25·|120 − 102.5| = 3.75 + 4.375 = 8.125 ms (הספר משתמש ב-EstRTT החדש; כתבו באיזה אתם משתמשים)
  3. Timeout = 102.5 + 4·8.125 = 135 ms
  4. עוד: N07

7. חלוקה ל-subnets עם VLSM

נתון

  • בלוק 200.1.1.0/24; צריך subnets ל-100, ‏50 ו-20 מחשבים.

פתרון

  1. מהגדול לקטן. 100 ← 128 ‏(/25): ‏200.1.1.0/25 (מחשבים ‎.1–.126, ‏broadcast ‎.127)
  2. 50 ← 64 ‏(/26): ‏200.1.1.128/26 (‎.129–.190, ‏broadcast ‎.191)
  3. 20 ← 32 ‏(/27): ‏200.1.1.192/27 (‎.193–.222, ‏broadcast ‎.223); ‎.224/27 נשאר פנוי
  4. עוד: N08

8. פיצול IPv4

נתון

  • Datagram של 4,000 בתים (20 header + 3,980 מידע), ‏MTU = 1,500.

פתרון

  1. מידע לכל fragment = 1,480 (מתחלק ב-8 ✓)
  2. Fragment 1: אורך 1,500, ‏offset 0, ‏MF = 1. ‏Fragment 2: אורך 1,500, ‏offset 185, ‏MF = 1. ‏Fragment 3: ‏1,020 מידע ← אורך 1,040, ‏offset 370, ‏MF = 0
  3. עוד: N08

4יום בחייה של בקשת web

סיימנו את המסע במורד מחסנית הפרוטוקולים. מחברים הכל יחד: סטודנט מחבר מחשב נייד לרשת הקמפוס ומבקש את www.google.com. כל פרוטוקול מהקורס מופיע, לפי הסדר.

התחברות לאינטרנט
  1. המחשב שהגיע צריך כתובת IP, את כתובת הנתב הראשון ושל שרת DNS: משתמשים ב-DHCP.
  2. בקשת ה-DHCP עטופה ב-UDP ‏(פורט 67), עטופה ב-IP ‏(יעד 255.255.255.255), עטופה ב-Ethernet ‏802.3 ‏(יעד FF-FF-FF-FF-FF-FF).
  3. ה-frame משודר ב-broadcast ב-LAN, מתקבל בנתב שמריץ את שרת ה-DHCP, ועובר demux מ-IP ל-UDP ל-DHCP.
  4. שרת ה-DHCP מכין DHCP ACK עם כתובת ה-IP של הלקוח, ה-IP של הנתב הראשון והשם וה-IP של שרת ה-DNS; הוא מועבר (switch שלומד) חזרה ללקוח.
ARP, ואז DNS
  1. לפני שליחת בקשת ה-HTTP צריך את ה-IP של www.google.com: DNS. שאילתת ה-DNS נוצרת ונעטפת ב-UDP, ב-IP וב-Ethernet. כדי לשלוח את ה-frame לנתב צריך את ה-MAC של ממשק הנתב: ARP.
  2. שאילתת ARP משודרת ב-broadcast, הנתב מקבל אותה ועונה עם ה-MAC של הממשק שלו. עכשיו הלקוח יודע את ה-MAC של הנתב הראשון ויכול לשלוח את ה-frame עם שאילתת ה-DNS.
  3. ה-datagram עם שאילתת ה-DNS מועבר דרך ה-switch מהלקוח לנתב הראשון, ואז מרשת הקמפוס לרשת ה-ISP, ומנותב (בטבלאות שנוצרו ע"י RIP, ‏OSPF, ‏IS-IS ו/או BGP) לשרת ה-DNS.
  4. שרת ה-DNS עושה demux ל-DNS ועונה ללקוח עם כתובת ה-IP של www.google.com.
TCP, ואז HTTP
  1. כדי לשלוח את בקשת ה-HTTP, הלקוח קודם פותח TCP socket לשרת: segment ‏TCP SYN (שלב 1 בלחיצת היד המשולשת) מנותב בין-תחומית לשרת ה-web.
  2. השרת עונה ב-TCP SYNACK (שלב 2); הלקוח שולח ACK (שלב 3): חיבור ה-TCP נוצר!
  3. בקשת ה-HTTP נשלחת לתוך ה-TCP socket; ה-datagram שמכיל אותה מנותב ל-www.google.com; השרת עונה עם HTTP reply (שמכיל את דף ה-web); ה-datagram עם התשובה מנותב חזרה ללקוח.
  4. עם HTTPS, לחיצת יד של TLS קורית בין TCP ל-HTTP (ראו פרק 07 בקורס האבטחה).
למה

הרצף הזה הוא עמוד השדרה של שני הקורסים: כל תקיפה בקורס האבטחה מכוונת לאחד מהשלבים האלה (DHCP starvation ו-rogue DHCP, ‏ARP poisoning, ‏DNS cache poisoning, ‏TCP SYN flood ו-RST injection, ‏TLS stripping). כדאי ללמוד אותו עד שאפשר לצייר אותו.

6אסטרטגיה למבחן

  1. קוראים כל שאלה פעם אחת ומסמנים את שאלות החישוב: הן הנקודות הכי צפויות.
  2. בכל חישוב כותבים: הנוסחה, הערכים עם יחידות, התוצאה עם יחידות. ניקוד חלקי נמצא בשתי השורות הראשונות.
  3. מציירים ציר זמן (שולח/מקבל, הזמן יורד למטה) לכל שאלה על RTT, לחיצות יד, ‏GBN/SR או התאוששות של TCP.
  4. בשאלות "הסבירו למה", מציינים את המנגנון ואת הבעיה שהוא פותר (למשל "לחיצת היד המשולשת מונעת חיבורים חצי-פתוחים מ-SYNים ישנים כפולים").
  5. שאלות אמריקאיות: פוסלים תשובות שמערבבות שכבות (למשל switch שמנתב לפי IP, או ARP שעובר נתב).
  6. משאירים 10 דקות לבדוק יחידות ואת כיוון אי-השוויונות (max מול min, ‏≤ מול <).
  7. תרגול: החידון בסוף כל פרק, ומצב התרגול המעורב ב-חידון תרגול.

7בדיקה אחרונה

מהם ארבעת רכיבי ההשהיה בצומת, ואיזה מהם תלוי בעומס?

עיבוד, תור, שידור, התפשטות. התור תלוי בעומס (ρ).

באיזה פרוטוקול תעבורה DNS משתמש בדרך כלל, ולמה?

UDP פורט 53: בקשה ותשובה קצרות, בלי עלות של handshake. ‏TCP לתשובות גדולות ו-zone transfers.

אחרי 3 ACKים כפולים, לאן TCP Reno מעדכן את cwnd ו-ssthresh?

ssthresh = cwnd/2, ‏cwnd = ssthresh + 3 MSS ‏(fast recovery), ואז congestion avoidance.

כמה כתובות מחשבים שמישות יש ב-/27?

25 − 2 = 30.

אילו כתובות משתנות מקפיצה לקפיצה: MAC, ‏IP או שתיהן?

רק MAC (ה-IP נשאר אלא אם NAT משנה אותו).
