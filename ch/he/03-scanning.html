פרק 03

סריקות רשת

איך תוקף ממפה רשת: מי חי (Ping sweep, ARP), אילו פורטים פתוחים (Connect, SYN, FIN, Xmas, Null, UDP, Idle), איך נשאר אנונימי, ואיך מזהים מערכת הפעלה באופן אקטיבי ופסיבי. ובצד השני: איך מזהים וחוסמים סריקות (Snort, ACL, הקטנת משטח תקיפה).

2פורטים ומצב של פורט

פורט הוא הפשטה של "מערכת הפעלה + שירות". מספר של 16 ביט בכותרת TCP ו-UDP. מרחבי TCP ו-UDP נפרדים, אבל נהוג להשתמש באותו מספר לשניהם (80/tcp ו-80/udp ל-www).

טווחשםדוגמאות
0–1023System / Well-knownftp 21, ssh 22, telnet 23, smtp 25, time 37, http 80, https 443
1024–49151User / RegisteredRDP 3389, MySQL 3306
49152–65535Dynamic / Privateפורטי מקור זמניים של לקוחות

Open

תהליך מאזין. SYN לפורט פתוח הוא החבילה הראשונה של ה-Handshake, ונענה ב-SYN/ACK.

Closed

אף תהליך לא מאזין. מערכת ההפעלה עונה על SYN ב-RST.

Filtered

Packet filter (Firewall) יושב על הפורט. אין תשובה, או ICMP unreachable.

Vertical scan

מארח אחד, הרבה פורטים. nmap 10.1.1.10 -p 1024-4423. "מה רץ על השרת הזה?"

Horizontal scan

פורט אחד, הרבה מארחים. nmap 10.1.1.0/24 -p 80. "מי ברשת מריץ שירות X?" כך עובדות תולעים.

3מי חי ברשת: Ping sweep ו-ARP scan

Ping sweep: שולחים ICMP Echo Request (Type 8) לכל כתובת בטווח. Echo Reply (Type 0) = המארח חי. אפשר להשתמש גם ב-ARP, TCP או UDP.

15 / 16Information Request / Reply
כשה-ICMP חסום 
# ping 192.168.0.2
Request timeout for icmp_seq 0          ← נראה "מת"
# hping2 192.168.0.2 -S -p 80
60 bytes from 192.168.0.2: flags=SA ...   ← SYN/ACK, הוא חי!

חסימת ICMP לא מסתירה מארח שמריץ שירות. שולחים SYN לפורט נפוץ (80, 443) וכל תשובה, גם RST, מוכיחה שהוא קיים.

ARP scan

שולחים ARP Request ("מי מחזיק את 192.168.1.X?") לכל כתובת בסגמנט.

יתרון

עובד בשכבה 2. Firewall במארח לא יכול להסתיר אותו, כי בלי לענות ל-ARP אי אפשר לתקשר בכלל.

חיסרון

עובד בשכבה 2. חייבים להיות באותו סגמנט, ולא עובר נתבים.

חשבון זמנים (מההרצאה)

Class B = 65,536 מארחים. Ping של שנייה למארח ≈ 18 שעות. פורט אחד לכל מארח ≈ עוד 18 שעות. Banner ל-10 שירותים בכל מארח (2 שניות) ≈ 15 ימים. Class A (16 מיליון) לוקח ימים.

איך מאיצים

קודם Host discovery ורק אז סריקת פורטים על החיים, לבחור פורטים רלוונטיים, ולפצל בין הרבה סורקים (בוטים). היום Masscan ו-ZMap סורקים את כל IPv4 בפורט אחד בפחות משעה, כי הם שולחים באופן אסינכרוני בלי לחכות לתשובה.

4תקיפות מבוססות ICMP: Smurf, Fraggle, Ping flood, Ping of death

Smurf (1997, smurf.c)

ICMP Echo לכתובת Broadcast עם IP מקור מזויף של הקורבן. כל מארח ברשת עונה לקורבן ומציף אותו. זו DDoS עם הגברה.

Fraggle

אותו רעיון עם UDP לפורט 7 (echo) ו-19 (chargen) בכתובת Broadcast. chargen עונה בזרם תווים, ולכן ההגברה גדולה יותר.

Ping flood

הצפה בכמות עצומה של Pings (ping -f ב-Unix). הדרישה היחידה: יותר רוחב פס מהקורבן.

Ping of Death

חבילת Ping פגומה. IP מוגבל ל-65,535 בייט; שולחים פרגמנטים שבהרכבה מחדש עוברים את הגבול, וגורמים ל-Buffer overflow וקריסה (מערכות של שנות ה-90).

הגנה

לא להעביר Directed broadcast בנתבים (no ip directed-broadcast, ברירת מחדל מאז 1999 בעקבות RFC 2644), לבטל שירותי echo/chargen, להגביל ICMP ב-ACL ל-DMZ ולמארחים ספציפיים, ו-Rate limiting. BCP 38 (Ingress filtering) מונע זיוף כתובות מקור.

RFC 793 קובע: חבילה בלי SYN שמגיעה לפורט סגור נענית ב-RST, ולפורט פתוח נזרקת בשקט. לכן אין תשובה = פתוח (או מסונן!). Windows לא עוקב אחרי ה-RFC ושולח RST תמיד, ולכן על Windows כל הפורטים נראים סגורים. זה עצמו מגלה את מערכת ההפעלה.

6סריקה אנונימית

Silent scan

nmap -sT -T sneaky -p 80,135,139 ...
מאט את הקצב (חבילה כל ~15 שניות) כדי לא לעבור את הסף של ה-IDS ("X חבילות בזמן Y").

Fragmentation scan

nmap -f ...
מפצל את כותרת ה-TCP לפרגמנטים קטנים. IDS או Firewall שלא מרכיבים חבילות מחדש לא רואים את הדגלים.

Decoy scan

nmap -D 1.1.1.1,2.2.2.2,ME,3.3.3.3 ...
שולח סריקות מזויפות מכתובות פיתיון לצד הסריקה האמיתית. היעד רואה 4 סורקים ולא יודע מי האמיתי.

הגנה

Snort מרכיב פרגמנטים (Preprocessor) לפני הבדיקה. ספי זמן ארוכים נגד Sneaky. ב-Decoy: ה-TTL של החבילות המזויפות שונה לפעמים מזה של האמיתית, ופיתיונות שלא קיימים לא מגיבים ל-SYN/ACK.

7Idle (Zombie) scan: לסרוק בלי לשלוח חבילה אחת מהכתובת שלך

מבוסס על IP ID צפוי: מארחים ישנים מעלים את שדה ה-IP ID ב-1 עם כל חבילה שהם שולחים. אם ה-Zombie "שקט" (Idle), אפשר לספור כמה חבילות הוא שלח. nmap -sI <zombie> <target>

למה זה עובד

ה-Zombie הוא "מונה" שהתוקף יכול לקרוא מרחוק. ההבדל בין 6 ל-7 הוא בדיוק החבילה (RST) שה-Zombie שלח לבד כתגובה ל-SYN/ACK מהיעד. בשלב 1 חוזרים כמה פעמים כדי לוודא שה-Zombie באמת שקט (IPID עולה ב-1 בדיוק).

הגנה

מערכות מודרניות (Linux, Windows 8+) משתמשות ב-IP ID אקראי או לכל יעד בנפרד, ולכן לא יכולות לשמש Zombie. מדפסות ומכשירי IoT ישנים עדיין מתאימים. Ingress filtering מונע את הזיוף, ו-Stateful firewall זורק SYN/ACK שלא ביקשו.

8סריקת UDP

nmap -sU שולח חבילת UDP ריקה (0 בייט). ICMP Port Unreachable (Type 3, Code 3) = סגור. כל דבר אחר = "פתוח" (Nmap מסמן open|filtered).

הבעיות
  1. אם Firewall חוסם את הפורט, אין תשובה, והפורט נראה פתוח.
  2. רוב מערכות ההפעלה מגבילות קצב הודעות ICMP Unreachable (Linux: אחת לשנייה), ולכן סריקה מלאה איטית מאוד.

Nmap משפר את זה עם Payloads ספציפיים לפרוטוקולים (שאילתת DNS לפורט 53, SNMP ל-161), שמקבלים תשובה אמיתית מפורט פתוח.

9זיהוי ומניעה של סריקות

זיהוי סריקות הוא התרעה מוקדמת לתקיפה. הכלי העיקרי: NIDS כמו Snort. זה שקיימת טכנולוגיה לזהות, לא אומר שמישהו מסתכל בזמן אמת.

Snort: IDS/IPS בקוד פתוח

מבוסס חוקים: Signatures, בדיקת פרוטוקולים ואנומליות. מזהה DoS, סריקות וניסיונות פריצה ע"י ניטור תעבורה.

alert tcp any any -> $HOME_NET any (flags:F; msg:"FIN scan"; sid:1000001;)
alert tcp any any -> $HOME_NET any (flags:FPU; msg:"Xmas scan"; sid:1000002;)
alert tcp any any -> $HOME_NET any (flags:0; msg:"Null scan"; sid:1000003;)

דוגמת חוקים להמחשה (לא מהשקפים).

מניעה

  • קשה מאוד למנוע סריקה. ממזערים חשיפה: לבטל כל שירות לא נחוץ (ב-Unix: /etc/inetd.conf וסקריפטי עלייה, ב-Windows: Services).
  • Ping sweep: להחליט איזה ICMP נכנס (למשל רק ל-DMZ ולמארחים ספציפיים), ACL לפי IP.
  • IPS יכול לזהות ולחסום, אבל יקר ויש False positives.
שאלה מההרצאה

פתח מנגנון שמזהה וחוסם Ping sweep. זיהוי: מקור אחד ששולח Echo Request ליותר מ-N כתובות שונות בחלון זמן (ההרצאה מציעה "ECHO request > ECHO reply ב-15 שניות", כלומר הרבה בקשות לכתובות שלא עונות). לגיטימי? כלי ניהול רשת שולחים Ping לפני חיבור, ולכן: Whitelist של שרתי ניהול, ובדיקה אם אחרי ה-Ping באמת נפתח חיבור (ניהול) או שהמקור עובר לכתובת הבאה (סריקה). חסימה: חסימה זמנית של המקור ב-Firewall (Shun) או Rate limit ל-ICMP ממנו.

10זיהוי מערכת הפעלה (OS Fingerprinting)

למה? Exploit עובד על מערכת וגרסה ספציפית. מימושי TCP/IP שונים זה מזה בפרטים שה-RFC לא קבע, וההבדלים האלה הם "טביעת אצבע".

Active · Banner grabbing

שירותים מכריזים מי הם (HTTP Server:, SSH SSH-2.0-OpenSSH_7.4 Debian, FTP 220 ProFTPD). קל, אבל אפשר לזייף.

Active · Stack fingerprinting

Nmap -O שולח חבילות "מוזרות" ומשווה תגובות ל-DB. דורש לרוב לפחות פורט פתוח אחד; בלי זה הדיוק נמוך.

Passive · Stack fingerprinting

לא שולחים כלום, רק מאזינים (מיקום מרכזי או Port mirror). כלים: Siphon, p0f. דורש גישה לתעבורה.

מגבלות

אפליקציות שבונות חבילות בעצמן (Nmap עצמו) נראות שונות מה-OS. צריך להיות במיקום שרואה את התעבורה. וקל לשנות את הפרמטרים האלה, מה שפוגע גם בזיהוי אקטיבי.

זיהוי ומניעה

זיהוי אקטיבי שולח חבילות חריגות, ולכן NIDS מזהה אותו בקלות; זו לא טכניקה חשאית. מניעה: אפשר לשנות פרמטרים של ה-Stack (למשל net.ipv4.ip_default_ttl), אבל זה עלול לפגוע בתאימות. "Security through obscurity" היא לא קו ההגנה הראשון: גם אם התוקף יודע את ה-OS, עדכונים והקשחה צריכים לעצור אותו.
