2Wireshark: לראות כל header

Wireshark לוכד חבילות בממשק ומפענח כל שכבה. בחלון יש שלושה חלקים: רשימת החבילות (שורה לכל frame), פרטי החבילה (עץ הפרוטוקולים: Ethernet ← IP ← TCP ← HTTP, אפשר לפתוח כל שדה), ו-בתי החבילה (hex). לחיצה על שדה מסמנת את הבתים שלו, וזו הדרך המהירה ביותר ללמוד מבני header.

לכידה ראשונה ב-6 צעדים
  1. פותחים Wireshark, לוחצים פעמיים על הממשק הפעיל (זה עם גרף התעבורה שזז: Wi-Fi או Ethernet).
  2. בטרמינל מריצים curl http://neverssl.com (HTTP רגיל, כך שאפשר לקרוא).
  3. עוצרים את הלכידה (הריבוע האדום). מקלידים את ה-display filter http || dns ולוחצים Enter.
  4. מוצאים את שאילתת ה-DNS והתשובה: פותחים Domain Name System, רואים את ה-Transaction ID, השאלה ורשומת ה-A.
  5. קליק ימני על ה-HTTP GET ← Follow ← TCP Stream: כל הבקשה והתשובה כטקסט.
  6. מנקים את הפילטר, מסננים tcp.stream eq N ‏(N מה-GET) ומוצאים את SYN, ‏SYN-ACK, ‏ACK, ואז את חילופי ה-FIN.

3tcpdump: לכידה משורת הפקודה

tcpdump הוא כלי הלכידה משורת הפקודה ב-Linux וב-macOS (ב-Windows: ‏Wireshark או pktmon). משתמשים בו בשרתים בלי ממשק גרפי, ואז פותחים את הקובץ השמור ב-Wireshark.

פקודהמה היא עושהקישור לחומר

sudo tcpdump -nn 'tcp[tcpflags] & tcp-syn != 0'רק סגמנטים עם SYNN07

sudo tcpdump -nn -e arpARP, עם כתובות MAC ‏(-e מדפיס את ה-header של שכבת הקו)N10

4ping: נגישות ו-RTT

ping שולח ICMP Echo Request ‏(type 8) ומודד כל Echo Reply ‏(type 0). הוא מודד RTT ואובדן. מחשב שלא עונה אולי פשוט חוסם ICMP, ולכן "אין תשובה" לא מוכיח שהוא כבוי.

פקודהמה היא עושהקישור לחומר
ping -c 5 8.8.8.85 גששים (Windows: ‏ping -n 5)N02
ping -s 1472 -M do 8.8.8.8מטען 1,472 + 8 ICMP + 20 IP = 1,500: בדיקת MTU של המסלול, עם DF (Windows: ‏ping -f -l 1472)N08
ping -i 0.2 -c 50 hostגששים מהירים יותר להערכת אובדן (Linux)
ping -t 3 hostקביעת ה-TTL ‏(Linux ‏-t, ‏Windows ‏-i): עם TTL נמוך מקבלים "Time to live exceeded" מנתבN09
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=21.4 ms
...
5 packets transmitted, 5 received, 0% packet loss
rtt min/avg/max/mdev = 20.9/21.6/22.8/0.7 ms     # mdev = jitter; variation comes from queueing delay
למה

עושים ping לשרת בעיר שלכם ולשרת ביבשת אחרת. ההבדל ב-RTT הוא כמעט כולו התפשטות: ~5 µs לכל ק"מ לכל כיוון בסיב. ‏10,000 ק"מ ≈ RTT של 100 ms, בלי קשר לרוחב הפס.

5traceroute, ‏tracert ו-mtr: המסלול

traceroute שולח גששים עם TTL = 1, 2, 3, …; הנתב ה-i זורק את הגשש שה-TTL שלו מגיע ל-0 ומחזיר ICMP Time Exceeded, וכך חושף את הכתובת שלו ואת ה-RTT אליו. ‏Linux/macOS שולחים כברירת מחדל UDP לפורטים גבוהים (היעד עונה Port Unreachable); ב-Windows ‏tracert משתמש ב-ICMP Echo. ‏mtr מריץ traceroute ברציפות ומראה אובדן לכל קפיצה.

פקודהמה היא עושהקישור לחומר
traceroute -n www.hit.ac.ilמסלול עם כתובות מספריות (מהיר יותר)N02
traceroute -I hostגששי ICMP Echo (כמו Windows)
traceroute -T -p 443 hostגששי TCP SYN לפורט 443: עוברים firewalls שזורקים UDP/ICMP
tracert -d hostWindows, בלי תרגום שמות
mtr -rwc 50 hostמצב דוח, 50 סבבים: אובדן ו-RTT לכל קפיצה
 1  192.168.1.1     1.2 ms  1.0 ms  1.1 ms      # home router
 2  10.120.0.1      8.5 ms  9.1 ms  8.7 ms      # ISP access
 3  * * *                                       # router that does not send ICMP: not a problem by itself
 4  62.219.x.x     12.3 ms 12.1 ms 12.8 ms
 9  142.250.x.x    58.4 ms 58.0 ms 58.9 ms      # big jump = long propagation (submarine cable)
מלכודת מבחן

אובדן שמופיע בקפיצה אחת באמצע אבל לא בקפיצות שאחריה הוא בדרך כלל הגבלת קצב ICMP בנתב הזה, לא אובדן אמיתי. אובדן אמיתי ממשיך עד היעד.

8netcat: ‏sockets ביד

netcat ‏(nc, או ncat מחבילת nmap ב-Windows) פותח socket גולמי של TCP או UDP ומחבר אותו למקלדת. זו הגרסה בשורת הפקודה של תוכניות ה-socket ב-N05.

פקודהמה היא עושהקישור לחומר

nc 127.0.0.1 5000טרמינל 2: מתחברים; מה שמקלידים מופיע בצד השניN05
nc -u -l 5001 / nc -u 127.0.0.1 5001אותו דבר מעל UDP: בלי לחיצת יד ב-WiresharkN05
printf "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n" | nc example.com 80לכתוב בקשת HTTP בעצמכםN03
nc -zv 127.0.0.1 20-25לבדוק אילו פורטים מקומיים מקבלים חיבור (על המחשב שלך)N06
לזכור

מריצים את זוג ה-TCP בזמן ש-Wireshark לוכד על ממשק ה-loopback ‏(lo / Npcap Loopback): רואים את לחיצת היד המלאה, סגמנטים של מידע עם PSH, ואת חילופי ה-FIN כשלוחצים Ctrl+C.

11iperf3: מדידת תפוקה
