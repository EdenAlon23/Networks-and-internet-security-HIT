שכבת הרשת: מישור הנתונים

שכבת הרשת מעבירה datagrams מהמחשב השולח למחשב המקבל, והיא השכבה הראשונה שרצה בכל נתב. הפרק הזה מכסה את מישור הנתונים, עבודת ההעברה בכל נתב: מה יש בתוך נתב, התאמת הקידומת הארוכה ביותר, ה-header של IPv4 ופיצול, מיעון וחלוקה לרשתות עם CIDR, ‏DHCP, ‏NAT, ‏IPv6, והעברה כללית ב-SDN.

מישור נתונים מול בקרהבתוך נתבהתאמת קידומת ארוכהBuffers ותזמוןIPv4 datagramפיצולמיעון ו-CIDRחלוקה לרשתותDHCPבלוקים של כתובותNATIPv6העברה כלליתחזרה

1מישור הנתונים ומישור הבקרה

מישור הנתונים (data plane)

פונקציה מקומית בכל נתב: קובעת איך datagram שהגיע לפורט כניסה מועבר לפורט יציאה (forwarding). ננו-שניות, בחומרה.

מישור הבקרה (control plane)

לוגיקה ברמת כל הרשת: קובעת איך datagram מנותב לאורך המסלול מהמקור ליעד (routing). שתי גישות: אלגוריתמי ניתוב מסורתיים שממומשים בכל נתב, ו-SDN ‏(software-defined networking) שממומש בשרתים מרוחקים. פרק N09.

מודל השירות של שכבת הרשת באינטרנט הוא best effort: אין הבטחה שהמסירה תצליח, אין הבטחה לזמן או לסדר המסירה, ואין הבטחה לרוחב פס. ארכיטקטורות אחרות (ATM, ‏IntServ) הציעו הבטחות, אבל best effort ניצח: מנגנונים פשוטים אפשרו פריסה רחבה, מספיק רוחב פס הופך אפליקציות זמן-אמת ל"טובות מספיק רוב הזמן", ו-CDN ושכפול בשכבת האפליקציה מקרבים שירותים למשתמשים.

2ארכיטקטורת נתב

לנתב יש פורטי כניסה, switching fabric, פורטי יציאה, ומעבד ניתוב (מישור הבקרה, תוכנה, בטווח של מילי-שניות). מישור ההעברה הוא חומרה שעובדת בננו-שניות.

חלקתפקידהערות
פורט כניסהסיום הקו (שכבה פיזית) ← פרוטוקול שכבת הקו (למשל Ethernet) ← חיפוש והעברה לפי שדות ה-header וטבלת ההעברה בזיכרון הפורט ("match plus action") ← תורהמטרה: לסיים את העיבוד ב"מהירות הקו". העברה לפי יעד משתמשת רק ב-IP היעד; העברה כללית משתמשת בכל שדה header

מלכודת מבחן

Head-of-the-line (HOL) blocking בפורטי הכניסה: אם ה-fabric איטי מכל פורטי הכניסה ביחד, נוצרים תורים בכניסות. datagram שעומד בראש התור חוסם את אלה שמאחוריו, גם אם פורט היציאה שלהם פנוי. זה שונה מ-HOL blocking של HTTP ‏(N03), אבל זה אותו רעיון.

3התאמת הקידומת הארוכה ביותר

טבלת העברה לא יכולה לפרט 4 מיליארד כתובות אחת-אחת, ולכן היא מפרטת טווחי כתובות (קידומות, prefixes). כשמחפשים את הרשומה המתאימה לכתובת יעד, משתמשים בקידומת הארוכה ביותר שמתאימה לכתובת. בחומרה עושים את זה במחזור שעון אחד עם TCAM ‏(ternary content addressable memory) שמשווה את כל הרשומות במקביל, כמיליון רשומות.

4Buffers ותזמון חבילות

כמה buffer? כלל האצבע ב-RFC 3439: buffer ממוצע שווה ל-RTT "טיפוסי" (נניח 250 ms) כפול קיבולת הקו C; למשל C = 10 Gbps ← ‏2.5 Gbit של buffer. המלצה חדשה יותר: עם N זרימות, RTT · C / √N. יותר מדי buffer מגדיל השהיה (bufferbloat), במיוחד בנתבים ביתיים; ‏TCP צריך buffer "מלא בדיוק מספיק".

6פיצול והרכבה מחדש

לקווי רשת יש MTU ‏(max transfer unit), ה-payload הגדול ביותר ב-frame של הקו; לסוגי קווים שונים יש MTU שונה (Ethernet: ‏1,500 בתים). datagram גדול מחולק ("מפוצל") בתוך הרשת: datagram אחד הופך לכמה, והם מורכבים מחדש רק ביעד הסופי. ביטים ב-IP header משמשים לזהות ולסדר את החלקים.

datagram של 4,000 בתים, ‏MTU = 1,500

נתון

  • אורך כולל 4,000 = 20 header + ‏3,980 מידע. ‏ID = x. ‏MTU 1,500 ← כל חלק נושא לכל היותר 1,480 בתים של מידע (כפולה של 8).

פתרון

  1. חלק 1: אורך 1,500, ‏ID x, ‏MF = 1, ‏offset 0
  2. חלק 2: אורך 1,500, ‏ID x, ‏MF = 1, ‏offset 1480/8 = 185
  3. חלק 3: מידע 3,980 − 2,960 = 1,020 ← אורך 1,040, ‏ID x, ‏MF = 0 (אחרון), ‏offset 2960/8 = 370
  4. בדיקה: 1,480 + 1,480 + 1,020 = 3,980 ✓. לכל חלק יש header משלו של 20 בתים, אז עוברים 3 headers במקום אחד.
לזכור

ה-offset ביחידות של 8 בתים כי יש לו 13 ביט אבל לאורך הכולל יש 16. לכן גודל המידע בכל חלק חוץ מהאחרון חייב להיות כפולה של 8. אם חלק אחד אבד, כל ה-datagram אבד (אין הרכבה חלקית). הדגל DF אוסר פיצול: הנתב אז זורק ושולח ICMP ‏"fragmentation needed", וכך עובד path-MTU discovery. נתבי IPv6 אף פעם לא מפצלים.

תקיפות שמבוססות על פיצול (Teardrop, ‏Ping of Death, סריקות עם fragments) מופיעות בקורס האבטחה: פרק 05 ו-פרק 03.

7מיעון IP ו-CIDR

כתובת IP היא מזהה של 32 ביט שמשויך לכל ממשק (interface) של מחשב או נתב (החיבור בין מחשב/נתב לקו פיזי). לנתבים יש בדרך כלל הרבה ממשקים; למחשב יש בדרך כלל אחד או שניים (Ethernet קווי, ‏802.11 אלחוטי). כתיבה עשרונית עם נקודות: 223.1.1.1 = 11011111 00000001 00000001 00000001.

Subnet היא קבוצה של ממשקים שיכולים להגיע זה לזה פיזית בלי לעבור דרך נתב. לכל הממשקים ב-subnet יש את אותם ביטים עליונים (חלק הרשת); הביטים התחתונים הם חלק המחשב. מתכון: מנתקים כל ממשק מהמחשב או הנתב שלו ונוצרים "איים" של רשתות מבודדות; כל אי הוא subnet. שימו לב שכל קו נקודה-לנקודה בין שני נתבים הוא subnet בפני עצמו.

CIDR ‏(Classless InterDomain Routing): לחלק הרשת יש אורך שרירותי. הפורמט a.b.c.d/x, כאשר x הוא מספר הביטים בחלק הרשת. דוגמה: 200.23.16.0/23 = 11001000 00010111 00010000 00000000 ← 23 ביטים של רשת, 9 ביטים של מחשב ← 29 = 512 כתובות (510 שמישות: חלק מחשב של אפסים הוא כתובת הרשת, וחלק של אחדות הוא כתובת ה-broadcast).

8חלוקה לרשתות צעד אחרי צעד

כתובת רשת, broadcast וטווח מחשבים

נתון

  • מחשב 172.16.45.200/20

פתרון

  1. /20 ← מסכה 255.255.240.0. הבית המעניין הוא השלישי: 45 = 0010 1101; משאירים את 4 הביטים העליונים ← 0010 0000 = 32
  2. כתובת רשת: 172.16.32.0; גודל הבלוק בבית השלישי: 256 − 240 = 16 ← הרשת הבאה היא 172.16.48.0
  3. Broadcast: 172.16.47.255; מחשבים 172.16.32.1 – 172.16.47.254 ‏(4,094 מחשבים)

חלוקה של /24 לשלוש מחלקות (VLSM)

נתון

  • בלוק 223.1.17.0/24. ‏subnet 1 צריך 90 ממשקים, subnet 2 צריך 60, ‏subnet 3 צריך 12.

פתרון

  1. מקצים קודם את הגדול. 90 ← צריך 128 כתובות ← /25: 223.1.17.0/25 ‏(.0–.127)
  2. 60 ← צריך 64 ← /26: 223.1.17.128/26 ‏(.128–.191)
  3. 12 ← צריך 16 ← /28: 223.1.17.192/28 ‏(.192–.207). השאר (.208–.255) נשאר פנוי.
  4. כל בלוק חייב להתחיל בכפולה של הגודל שלו, ולכן הקצאה מהגדול לקטן מונעת חורים.
מלכודת מבחן

לזכור לספור את כתובת הרשת ואת ה-broadcast (ואם השאלה אומרת, גם את הממשק של הנתב) כשבוחרים גודל בלוק: 62 מחשבים נכנסים ב-/26 ‏(64 − 2), אבל 63 לא.

9DHCP: ‏Dynamic Host Configuration Protocol

איך מחשב מקבל כתובת IP? או שמנהל המערכת מגדיר אותה בקובץ הגדרות, או באופן דינמי משרת בעזרת DHCP: ‏"plug-and-play". מטרות: לחדש את החכירה (lease) של כתובת בשימוש, לשחזר כתובות (כתובת מוחזקת רק כל עוד המחשב מחובר), ולתמוך במשתמשים ניידים שמצטרפים ועוזבים. ‏DHCP רץ מעל UDP, פורט שרת 67, פורט לקוח 68.

DORA
  1. Discover (broadcast אופציונלי): src 0.0.0.0:68 ← dst 255.255.255.255:67, ‏yiaddr 0.0.0.0, ‏transaction ID 654. "יש פה שרת DHCP?"
  2. Offer: src 223.1.2.5:67 ← dst 255.255.255.255:68, ‏yiaddr 223.1.2.4, ‏transaction ID 654, ‏lifetime 3600 s. "אני שרת DHCP! הנה כתובת IP שאפשר להשתמש בה."
  3. Request ‏(broadcast, כדי ששרתים אחרים שהציעו יידעו שלא נבחרו): yiaddr 223.1.2.4, ‏transaction ID 655. "אני לוקח את הכתובת הזו!"
  4. ACK: ‏yiaddr 223.1.2.4, ‏transaction ID 655, ‏lifetime 3600 s. "בסדר. הכתובת שלך."

DHCP מחזיר יותר מכתובת IP: את כתובת הנתב הראשון (default gateway), את השם וה-IP של שרת ה-DNS, ואת מסכת הרשת (איזה חלק רשת ואיזה מחשב). שרת ה-DHCP יושב בדרך כלל בנתב הביתי או בנתב הקמפוס. שרתי DHCP זדוניים והרעבת DHCP מוסברים בפרק 04 בקורס האבטחה.

10איך רשתות מקבלות בלוקים; צבירת מסלולים

רשת מקבלת חלק ממרחב הכתובות של ה-ISP שלה. דוגמה: ל-ISP יש 200.23.16.0/20 והוא מחלק אותו ל-8 בלוקים של ‎/23: ארגון 0 מקבל 200.23.16.0/23, ארגון 1 מקבל 200.23.18.0/23, … ארגון 7 מקבל 200.23.30.0/23.

מיעון היררכי מאפשר פרסום יעיל של מידע ניתוב: ה-ISP אומר לשאר האינטרנט רק "שלחו לי כל דבר שמתחיל ב-200.23.16.0/20" (צבירת מסלולים). אם ארגון 1 עובר ל-ISP אחר, ה-ISP הזה מפרסם את המסלול הספציפי יותר 200.23.18.0/23; התאמת הקידומת הארוכה גורמת לו לנצח את המסלול המצטבר.

מי נותן לספקים את הבלוקים? ‏ICANN מקצה ל-5 הרשמים האזוריים (RIRs: ‏ARIN, ‏RIPE NCC (אירופה וישראל), ‏APNIC, ‏LACNIC, ‏AfriNIC), שמקצים לספקים. נתח ה-IPv4 האחרון הוקצה ב-2011; ‏NAT ו-IPv6 הם התשובות להתרוקנות.

11NAT: ‏Network Address Translation

כל המכשירים ברשת מקומית חולקים כתובת IPv4 אחת בלבד מבחינת העולם החיצוני. בפנים הם משתמשים בכתובות פרטיות (למשל 10.0.0.0/24); לכל datagram שיוצא מהרשת יש אותו IP מקור (למשל 138.76.29.7) ופורט מקור שונה.

התרגום צעד אחרי צעד
  1. המחשב 10.0.0.1 שולח datagram ל-128.119.40.186:80 ממקור 10.0.0.1:3345.
  2. נתב ה-NAT משנה את כתובת המקור ל-138.76.29.7:5001 ומוסיף רשומה לטבלת התרגום: 138.76.29.7, 5001 ↔ 10.0.0.1, 3345.
  3. התשובה מגיעה לכתובת 138.76.29.7:5001.
  4. הנתב מחפש בטבלה ומשנה את היעד ל-10.0.0.1:3345, ואז מעביר פנימה.
  • יתרונות: IP אחד מה-ISP לכל המכשירים; אפשר לשנות כתובות פנימיות בלי להודיע לעולם; אפשר להחליף ISP בלי לשנות כתובות פנימיות; מכשירים פנימיים לא נגישים ישירות מבחוץ (תופעת לוואי, לא אבטחה אמיתית).
  • שדה הפורט של 16 ביט מאפשר כ-60,000 חיבורים בו-זמנית עם כתובת אחת.
  • מחלוקות: נתבים "אמורים" לעבד רק עד שכבה 3, אבל NAT משכתב פורטים (שכבה 4); את המחסור בכתובות "אמור" לפתור IPv6; זה מפר את עקרון קצה-לקצה; NAT traversal: מה אם לקוח מבחוץ רוצה להתחבר לשרת מאחורי NAT? (port forwarding סטטי, ‏UPnP, ממסר כמו STUN/TURN). ובכל זאת NAT נמצא בכל מקום: נתבים ביתיים, רשתות ארגוניות, סלולר 4G/5G ‏(carrier-grade NAT).

שדות ה-header המדויקים ש-NAT משכתב (וה-checksums) מופיעים בפרק 09 בקורס האבטחה.

13העברה כללית ו-SDN

בכל נתב יש flow table שמחושבת ומופצת ע"י בקר מרכזי לוגית. העברה כללית היא "match plus action": להתאים ביטים ב-headers של packets שמגיעים, בכל שכבה, ולבצע פעולה: drop, forward (לפורט), modify של שדות, או שליחה לבקר. לכל כלל יש גם עדיפות (כדי להכריע בין תבניות חופפות) ומונים (מספר בתים ומספר packets).

OpenFlow examples (match → action)
  IP Dst = 51.6.0.8                        → forward(port 6)          # destination-based forwarding
  TCP Dst Port = 22                        → drop                     # firewall: block ssh
  IP Src = 128.119.1.1                     → drop                     # block a host
  MAC Dst = 22:A7:23:11:E1:02              → forward(port 3)          # layer-2 switching

כך אבסטרקציה אחת מאחדת נתב, switch, ‏firewall ו-NAT. Middleboxes ‏(NAT, ‏firewalls, ‏IDS, ‏load balancers, מטמונים) היו פעם קופסאות קנייניות נפרדות; ‏NFV ‏(network functions virtualization) מריץ אותן כתוכנה על חומרה רגילה, ומתכנת אותן עם SDN.
