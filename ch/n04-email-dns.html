E-mail and DNS

Lecture 4 covers two application protocols that everything else depends on. E-mail shows a push protocol (SMTP) next to pull protocols (IMAP, POP3) and a text-based command/response dialogue. DNS shows how a distributed, hierarchical database answers billions of name lookups a day, mostly from caches.

1E-mail: three major components

ComponentRole
User agent (mail reader)Compose, edit, read messages: Outlook, Apple Mail, Thunderbird, a webmail page. Outgoing and incoming messages are stored on the server.
Mail serversA mailbox holds incoming messages for each user; a message queue holds outgoing messages waiting to be sent.
SMTPSimple Mail Transfer Protocol (RFC 5321): moves messages between mail servers. The sending server acts as the SMTP client, the receiving server as the SMTP server.
Alice sends a message to Bob
  1. Alice composes a message to bob@someschool.edu in her user agent.
  2. Her UA sends it to her mail server (submission, SMTP on port 587); the message is placed in the message queue.
  3. Alice's server, as SMTP client, looks up the MX record of someschool.edu in DNS and opens a TCP connection to Bob's server on port 25.
  4. It sends the message over that connection with the SMTP dialogue.
  5. Bob's server places the message in Bob's mailbox.
  6. Bob's UA reads it with a pull protocol: IMAP or HTTP (webmail).
Remember

There is no direct connection between Alice's and Bob's computers, and usually no intermediate mail servers: Alice's server talks directly to Bob's server. If Bob's server is down, the message stays in Alice's server queue and is retried (typically every 30 minutes for a few days).

2SMTP properties

  • Uses TCP to reliably transfer messages, server port 25.
  • Three phases of transfer: handshaking (greeting), transfer of messages, closure.
  • Command/response interaction, like HTTP: commands are ASCII text, responses are a status code and phrase.
  • Messages (header and body) must be in 7-bit ASCII. Binary attachments are encoded to ASCII with MIME (base64).
  • Persistent connections: several messages to the same server go over one TCP connection.
  • The end of a message is marked by CRLF.CRLF (a line with a single dot).
HTTPSMTP
DirectionPull: the client pulls objects from the serverPush: the client pushes the message to the server

3A full SMTP dialogue

S = server (crepes.fr receiving), C = client (hamburger.edu sending). Before this, a TCP handshake to port 25 took 1 RTT.

S: 220 hamburger.edu                         ← greeting
C: HELO crepes.fr                             ← handshake (EHLO for extended SMTP)
S: 250 Hello crepes.fr, pleased to meet you
C: MAIL FROM: <alice@crepes.fr>              ← envelope sender
S: 250 alice@crepes.fr... Sender ok
C: RCPT TO: <bob@hamburger.edu>              ← envelope recipient (repeat for each)
S: 250 bob@hamburger.edu ... Recipient ok
C: DATA
S: 354 Enter mail, end with "." on a line by itself
C: Do you like ketchup?
C: How about pickles?
C: .                                           ← end of message (CRLF.CRLF)
S: 250 Message accepted for delivery
C: QUIT
S: 221 hamburger.edu closing connection

Try it yourself in a lab: telnet <servername> 25 and type the commands. (Real servers today require STARTTLS and authentication for submission, and spam filters reject most hand-typed mail.)

Exam trap

The envelope (MAIL FROM / RCPT TO) is what servers route on; the From: / To: lines inside DATA are just text the user sees. Nothing in plain SMTP checks that they match, which is exactly why spoofing works and why SPF, DKIM and DMARC exist (security chapter 08).

4Mail message format (RFC 5322) and MIME

RFC 5321 (SMTP) defines how to transfer a message; RFC 5322 defines the message itself: header lines, a blank line, then the body (ASCII only).

From: alice@crepes.fr
To: bob@hamburger.edu
Subject: Searching for the meaning of life.
MIME-Version: 1.0
Content-Type: multipart/mixed; boundary="XYZ"

--XYZ
Content-Type: text/plain; charset=UTF-8

Hi Bob, see the picture.
--XYZ
Content-Type: image/jpeg
Content-Transfer-Encoding: base64

/9j/4AAQSkZJRgABAQEASABIAAD...
--XYZ--

MIME (Multipurpose Internet Mail Extensions) adds headers that declare the content type and the encoding, so binary data (images, PDFs) and non-English text can travel inside a 7-bit ASCII message. Base64 turns every 3 bytes into 4 ASCII characters (33% larger).

5Mail access protocols: IMAP, POP3, HTTP

SMTP is a push protocol, so the recipient cannot use it to fetch mail from its own server. A pull protocol is needed for the last step.

ProtocolPortBehaviour
IMAP143 (993 TLS)Messages stay on the server. Supports folders, retrieval, deletion, flags. Keeps state across sessions, so all your devices see the same mailbox.
POP3110 (995 TLS)Authorization phase (user, pass), then transaction phase (list, retr, dele, quit). "Download and delete" mode removes mail from the server, so a second device sees nothing; "download and keep" leaves copies. Stateless across sessions.
HTTP(S)443Webmail (Gmail, Outlook.com): the browser talks HTTPS to the web server, which uses IMAP/SMTP behind the scenes.

6DNS: what it provides and why it is distributed

People use names (www.yahoo.com); routers use 32-bit IP addresses. The Domain Name System maps between them. It is a distributed database implemented in a hierarchy of many name servers, and an application-layer protocol that hosts and servers use to query it. It runs over UDP port 53 (TCP 53 for large answers and zone transfers).

ServiceMeaning
Hostname → IP translationThe main job (A / AAAA records)
Host aliasingA canonical name with easier aliases (CNAME)
Mail server aliasing@company.com → the actual mail server (MX)
Load distributionMany IPs for one name; DNS rotates the order (replicated web servers, CDNs)
Why

Why not one central DNS server? It would be a single point of failure, would carry the whole world's query volume (Akamai alone sees trillions of queries a day), would be far from most users, and would be impossible to maintain. "It doesn't scale."

8Iterative vs recursive resolution

Host cis.poly.edu wants the IP of gaia.cs.umass.edu. It always asks its local DNS server (that first query is recursive: "get me the answer").

Iterated query (the usual case)

The local server asks the root → the root answers "I don't know, ask the .edu TLD at this address" (a referral) → the local server asks the TLD → referral to umass.edu's authoritative server → the local server asks it and gets the A record.

8 messages: host↔local (2) + local↔root (2) + local↔TLD (2) + local↔authoritative (2). The load stays on the local server.

Recursive query

Each server asks the next one on behalf of the previous: local → root → TLD → authoritative, and the answer travels back along the same chain.

Also 8 messages, but it puts a heavy load on the upper levels, so root and TLD servers do not do it in practice.

Caching and TTL

Once any server learns a mapping, it caches it for the record's TTL. TLD server addresses are usually cached in local servers, so the root is rarely visited. Cached entries may be out of date: if a host changes its IP, the world may not know until all TTLs expire ("best-effort name-to-address translation").

DNS + HTTP timing (classic)

Given

  • The host's local DNS cache is empty. Resolving the name needs n DNS servers with RTTs RTT1…RTTn. RTT0 to the web server; the page is one small object.

Solution

  1. Time from click to page = (RTT1 + … + RTTn) + 2·RTT0
  2. Without any cache, each of the 3 levels (root, TLD, authoritative) costs a query: three times the per-query time on top of the local server RTT.
  3. A second visit within the TTL skips DNS entirely.

11Putting your domain into DNS

Example: startup "Network Utopia"
  1. Register networkutopia.com with a registrar (accredited by ICANN). Provide the names and IPs of your authoritative name servers (primary and secondary).
  2. The registrar inserts two records into the .com TLD server: (networkutopia.com, dns1.networkutopia.com, NS) and (dns1.networkutopia.com, 212.212.212.1, A).
  3. On your authoritative server, create the A record for www.networkutopia.com and the MX record for networkutopia.com.

13Review

Why is SMTP called a push protocol, and what does Bob use to read his mail?

The sender initiates the connection and pushes the message to the receiving server. Bob pulls it from his server with IMAP, POP3 or HTTP.

Which record does Alice's mail server look up to deliver to @someschool.edu?

The MX record of someschool.edu, then the A record of the mail server it names.

In an iterative resolution, who does the work?

The local DNS server: it sends each query itself and follows the referrals from root to TLD to authoritative.

What happens to a cached record after its TTL?

It is discarded, and the next lookup goes to the hierarchy again.

Why does DNS use UDP?

Queries are small and must be fast: no handshake RTT and no connection state on busy servers. The client simply retries on loss; TCP is used when the answer is too big (TC flag) or for zone transfers.
