1What cryptography gives us, and basic terms

Confidentiality

Only the sender and receiver "understand" the message.

Authentication

Both sides verify each other's identity.

Message integrity

Any change to the message (in transit or later) is detected.

Symmetric

The same key on both sides (shared secret, conventional, secret key). The only kind until the 1970s and still the most used, because it is fast.

Asymmetric (public key)

Different keys. Published in 1976 (Diffie-Hellman). Next chapter.

Block vs stream

Block: processes a block (64 or 128 bits) at a time. Stream: processes continuously, a bit or byte at a time.

Substitution vs transposition

Substitution: each letter/bit maps to another. Transposition: same symbols, different order.

Who are Alice and Bob in real life? A browser and a server during a purchase, online banking, DNS servers, routers exchanging routing tables. Trudy can intercept, delete and insert messages.

2The five components and Kerckhoffs's principle (1883)

Every encryption scheme has five parts: plaintext, encryption algorithm, key(s), ciphertext, decryption algorithm. Security depends on the secrecy of the key, not of the algorithm.

Kerckhoffs

A cryptosystem should be secure even if everything about it except the key is public. Why that is convenient:

  • Only a short key must stay secret.
  • If the key leaks, you replace the key, not the whole system.
  • It enables standards: every vendor implements the same algorithm (e.g. SSL).
  • Ethical hackers and researchers can examine the algorithm.
  • The same system is reused with different keys.

Strong encryption: an attacker who knows the algorithm, some ciphertext, and maybe some plaintext–ciphertext pairs cannot deduce the plaintext or the key. Stronger still: the attacker learns nothing about m except its length (Ferguson, Schneier, Kohno).

When the principle is violated

"Security through obscurity" breaks again and again: DVD CSS (1999), Crypto-1 in MIFARE Classic cards (2008, reverse-engineered from the chip), A5/1 in GSM, and KeeLoq in car keys. All were secret, all were broken once exposed.

3Cryptanalysis and brute force

Brute force

Try every key. On average half the key space is needed. Impractical if the key is long enough.

Exploiting a weakness

In the algorithm, or in the key: e.g. a key derived from a badly chosen password.

Is any encryption unbreakable?

In theory only the One-Time Pad. In practice a system is computationally secure if the cost of breaking it exceeds the value of the information, or the time to break it exceeds the useful life of the information.

Key management is the hard part in practice: distribution, transfer, storage, access and lifetime.

4Classical ciphers, and how to break each one

Caesar cipher

Cyclic shift: c = (p + k) mod 26, p = (c − k) mod 26. With k = 3: attack at dawn → DWWDFN DW GDZQ. Monoalphabetic: each letter always maps to the same letter (one-to-one).

Try it

Breaking it

Brute force: only 25 keys. Easy.

Monoalphabetic substitution

Arbitrary letter mapping: ABC...Z → XDQ...T. attack at dawn → XCCXQJ XC MXBF.

Breaking it

Brute force is hard: 26! ≈ 4 × 1026 keys. But frequency analysis breaks it easily: in English E is most common, then T, A, O. Also digrams (th, an, ed) and trigrams (ing, the, est). Lesson: a huge key space is not enough if the structure leaks.

Polyalphabetic: Vigenère

Each occurrence of a letter can get a different substitute (one-to-many). A repeating keyword is "added": effectively 26 Caesar ciphers that alternate.

key:        witwitwitwitwitwitwitwitwit
plaintext:  wearediscoveredsaveyourself
ciphertext: SMTNMWEAVKDXNMWOIOAGHQZLATY
Breaking it

The trick is to find the key length (Kasiski: distances between repeated sequences; Friedman: index of coincidence). If the length is 3, split into three Caesar ciphers (SNEKNOAQA, MMADMIGZT, TWVXWOHLY) and break each with frequency analysis.

Transposition

Symbols stay the same but change position. Rail fence: write in a zig-zag over several "rails" and read row by row.

a t c a m d i h
 t a k t i n g t   →  ATCAMDIHTAKTINGT

The Spartan scytale (5th century BC): a strip wound around a rod of a certain diameter. The diameter is the key. Modern ciphers are product ciphers that combine substitution and transposition.

5One-Time Pad: perfect encryption

A random key, as long as the message, used only once. In bits: C = P ⊕ K. Unconditionally secure (Shannon, 1949): every plaintext of that length is equally likely, so the ciphertext gives no information.

Why it is not used

You must transfer in advance a key as long as all future traffic, over a secure channel. If you had such a channel, you could send the message itself over it. Used for: the Washington–Moscow "red line", spies.

If the key is used twice

C1 ⊕ C2 = P1 ⊕ P2: the key cancels, leaving two "mixed" texts that are easy to separate with language analysis. That is how project VENONA decrypted Soviet cables whose pads had been reused. The same mistake broke WEP (a 24-bit IV repeated with RC4).

6Steganography: hiding that a message exists

From Greek steganos (covered) + graphy (writing). An alternative to encryption: instead of not understanding the message, nobody knows there is one. Historically: invisible ink, marked letters in a text, a message tattooed on a shaved head.

Digitally: in text, images, audio, compressed files. Methods from the lecture:

  • Binary copy: append the message to the end of the file (copy /b image.bmp + secret.zip out.bmp). The image opens normally, but the file is bigger.
  • NULL bit / LSB replacement: replace the least significant bit of each colour byte. A ±1 change in a colour value is invisible.
  • Mix and encrypt: encrypt the message, then hide it, so even if found it cannot be read.
Use in attacks

Malware hides payloads inside images (Stegoloader, malicious ads), and C&C passes commands inside images on social networks. Also data exfiltration from an organization inside innocent files.

Detection (steganalysis)

Compare file sizes, statistical analysis of the LSBs (in a natural image they are not fully random), tools like StegExpose and binwalk (finds appended files). Downside of steganography: high overhead to hide little data.

The last property is the whole story: the same operation encrypts and decrypts. And it is very fast in hardware.

Stream cipher

A keystream generator produces a pseudo-random bit stream from the key, XORed with the message. The receiver generates the same keystream to recover the message. Examples: RC4, Rabbit, today ChaCha20.

Block cipher

A permutation over all bits of the block at once. One error affects the whole block and there is latency, but no synchronization problem, and it is better studied. Examples: 3DES, AES, Twofish, Blowfish. A short message is padded (e.g. PKCS#7: 05 05 05 05 05).

8Modes of operation: ECB vs CBC

A block cipher encrypts one block. How do you encrypt a long message? Modes: ECB, CBC, CFB, OFB, CTR (and GCM, not on the slides).

ECB · Electronic Codebook

Each block encrypted separately, like a code book. Efficient and parallel.
The problem: identical plaintext → identical ciphertext. Patterns remain. The "ECB penguin": an image encrypted in ECB where you still see the penguin.

CBC · Cipher Block Chaining

Ci = EK(Mi ⊕ Ci−1), C0 = IV (random). Each block depends on all previous ones, so patterns disappear.
Limits: an error in one block affects decryption of the next block (only that one), both sides need the IV, encryption is not parallel (decryption is).

Attacks on modes

ECB: reveals patterns and allows swapping blocks (cut & paste). Adobe leak 2013: passwords in 3DES-ECB; identical passwords were spotted by identical ciphertext plus password hints.
CBC with a predictable IV: BEAST (2011) against TLS 1.0.
CBC + padding: padding oracle (Vaudenay 2002, POODLE 2014, Lucky13): the server reveals whether padding is valid, which is enough to decrypt byte by byte.

In practice today

AES-GCM or ChaCha20-Poly1305: AEAD modes (authenticated encryption) that give both confidentiality and integrity. TLS 1.3 allows only those.

9The Feistel network

Li = Ri−1
Ri = Li−1 ⊕ F(Ki, Ri−1)
Why Feistel is brilliant

Decryption is identical to encryption, just with the subkeys in reverse order. And it works even if F is not invertible: since Ri−1 = Li is known, you can recompute F(Ki, Li) and undo the XOR. So F can be as complicated as you like, and one piece of hardware does both directions.

Parameters that vary between algorithms: block size, key size, subkey generation algorithm, number of rounds, round function F.

DES

Feistel with initial and final permutations, 16 rounds, each using 48 bits of the key. A complex mix of substitution and transposition.
How secure? DES Challenge (1997): 3,500 computers, 4 months. 1998: EFF's $100,000 "DES Cracker" found a key in 4 days. No known backdoor; the only problem is key length.

3DES

C = EK3(DK2(EK1(P)))
P = DK1(EK2(DK3(C)))
Why E-D-E and not E-E-E? If K1=K2=K3 it is exactly plain DES: backward compatibility. Also possible with 2 keys (K1=K3, 112 bits).
Why not 2DES? Meet-in-the-middle cuts security to ~257; for the same reason 3DES really gives ≈ 112 bits, not 168.

AES

Chosen in an open competition (Rijndael, Belgium). Requirements: public domain, no royalties, 128-bit block, 128/192/256-bit keys, speed on different processors, small memory (smart cards), simplicity, hardware and software.
A brute force that takes one second for DES would take 149 trillion years for AES.

Real world

AES is everywhere: TLS, WPA2/3, BitLocker, FileVault, Signal, ZIP. CPUs have hardware instructions (AES-NI). Practical attacks on AES target the implementation, not the algorithm: side channels (cache timing, power) and leaked keys. 3DES was retired in 2023 (NIST), partly because of Sweet32 (a 64-bit block collides after 232 blocks).

11Where to place encryption

End-to-end

Only the source and destination hold a key. Suits a partly untrusted network. But headers are in the clear (they must be routed), so traffic patterns (who talks to whom, when, how much) are not protected. Examples: TLS, Signal, PGP.

Link encryption

An encryption device at each end of every link. Each neighbour pair shares a key. Hides headers on the wire too, but every node sees everything. Examples: WPA2 (client to AP), MACsec, line encryption between sites.

12Diffie-Hellman: agreeing on a key over an insecure channel

The big problem of symmetric encryption: how do Alice and Bob agree on KAB if the whole channel is recorded? DH solves it without ever sending the key.

  1. Public: a large prime N and a generator G.
  2. Alice picks secret x, sends X = Gx mod N.
  3. Bob picks secret y, sends Y = Gy mod N.
  4. Alice computes K = Yx mod N; Bob computes K = Xy mod N. Same value.
Why it works

(Gy)x = (Gx)y = Gxy mod N. Eve sees Gx and Gy, but to compute Gxy she needs x or y, i.e. to solve the discrete logarithm, which is computationally hard when N is huge (2048 bits and up). With 23 you could just try everything.

The weakness: MITM

DH alone does not authenticate who is on the other side. Trudy can run a separate DH with each side (just like ap5.0 in chapter 01) and relay messages between them. Fix: sign the DH values (TLS: the server signs with its certificate key), or verify a fingerprint (Signal safety number). Logjam (2015) downgraded TLS connections to 512-bit DH.

Real world

ECDHE (DH over elliptic curves) in every TLS 1.3 connection, SSH, IPsec (IKE), WireGuard and Signal. "E" = ephemeral: a new key per connection, so Perfect Forward Secrecy: even if the server's private key leaks tomorrow, past sessions stay closed.
