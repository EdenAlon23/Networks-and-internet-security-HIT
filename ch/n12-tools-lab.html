Network tools lab: guides and commands

Every concept in this course can be seen on a real machine with a handful of free tools. For each tool: what it is for, how to run it on Linux, macOS and Windows, the commands you will actually use, how to read the output, and a short exercise that ties it to a chapter. All of these are safe, read-only diagnostics on your own machine and network.

2Wireshark: see every header

Wireshark captures packets on an interface and decodes every layer. The window has three panes: the packet list (one line per frame), packet details (the protocol tree: Ethernet → IP → TCP → HTTP, expand any header field), and packet bytes (hex). Clicking a field highlights its bytes, which is the fastest way to learn header formats.

First capture in 6 steps
  1. Open Wireshark, double-click your active interface (the one with a moving traffic graph: Wi-Fi or Ethernet).
  2. In a terminal run curl http://neverssl.com (plain HTTP, so it is readable).
  3. Stop the capture (red square). Type the display filter http || dns and press Enter.
  4. Find the DNS query and response: expand Domain Name System, see the Transaction ID, the question and the A record.
  5. Right-click the HTTP GET → Follow → TCP Stream: the full request and response as text.
  6. Clear the filter, filter tcp.stream eq N (N from the GET) and find the SYN, SYN-ACK, ACK, then the FIN exchange.

4ping: reachability and RTT

ping sends ICMP Echo Request (type 8) and times each Echo Reply (type 0). It measures RTT and loss. A host that does not answer may simply block ICMP, so "no reply" does not prove it is down.

CommandWhat it doesCourse link
ping -c 5 8.8.8.85 probes (Windows: ping -n 5)N02
ping -s 1472 -M do 8.8.8.81,472 B payload + 8 ICMP + 20 IP = 1,500: test the path MTU, DF set (Windows: ping -f -l 1472)N08
ping -i 0.2 -c 50 hostFaster probes for a loss estimate (Linux)
ping -t 3 hostSet the IP TTL (Linux -t, Windows -i): with a low TTL you get "Time to live exceeded" from a routerN09
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=21.4 ms
...
5 packets transmitted, 5 received, 0% packet loss
rtt min/avg/max/mdev = 20.9/21.6/22.8/0.7 ms     # mdev = jitter; variation comes from queueing delay
Why

Ping a server in your city and one on another continent. The RTT difference is almost all propagation: ~5 µs per km each way in fiber. 10,000 km ≈ 100 ms RTT, whatever your bandwidth.

5traceroute, tracert and mtr: the path

traceroute sends probes with TTL = 1, 2, 3, …; router number i drops the probe whose TTL reaches 0 and returns ICMP Time Exceeded, revealing its address and the RTT to it. Linux/macOS send UDP to high ports by default (the destination answers Port Unreachable); Windows tracert uses ICMP Echo. mtr runs traceroute continuously and shows loss per hop.

CommandWhat it doesCourse link
traceroute -n www.hit.ac.ilPath with numeric addresses (faster)N02
traceroute -I hostUse ICMP Echo probes (like Windows)
traceroute -T -p 443 hostTCP SYN probes to port 443: passes firewalls that drop UDP/ICMP
tracert -d hostWindows, no name lookups
mtr -rwc 50 hostReport mode, 50 rounds: loss and RTT per hop
 1  192.168.1.1     1.2 ms  1.0 ms  1.1 ms      # home router
 2  10.120.0.1      8.5 ms  9.1 ms  8.7 ms      # ISP access
 3  * * *                                       # router that does not send ICMP: not a problem by itself
 4  62.219.x.x     12.3 ms 12.1 ms 12.8 ms
 9  142.250.x.x    58.4 ms 58.0 ms 58.9 ms      # big jump = long propagation (submarine cable)
Exam trap

Loss shown at one middle hop but not at the following hops is usually ICMP rate-limiting on that router, not real loss. Real loss continues to the destination.

8netcat: sockets by hand

netcat (nc, or ncat from the nmap package on Windows) opens a raw TCP or UDP socket and connects it to your keyboard. It is the shell version of the socket programs in N05.

CommandWhat it doesCourse link
nc -l 5000Terminal 1: a TCP server listening on port 5000 (some versions: nc -l -p 5000)N05
nc 127.0.0.1 5000Terminal 2: connect; whatever you type appears on the other sideN05
nc -u -l 5001 / nc -u 127.0.0.1 5001The same over UDP: no handshake in WiresharkN05
printf "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n" | nc example.com 80Type an HTTP request yourselfN03
nc -zv 127.0.0.1 20-25Check which local ports accept a connection (your own machine)N06
Remember

Run the TCP pair while Wireshark captures on the loopback interface (lo / Npcap Loopback): you will see the full handshake, data segments with PSH, and the FIN exchange when you press Ctrl+C.

Exam trap

Read your routing table as a longest-prefix-match table: the default (0.0.0.0/0) route points to your gateway, and the connected /24 (or similar) route says your own subnet is reached directly, with ARP, not through the router.

11iperf3: measure throughput

CommandWhat it doesCourse link
iperf3 -sRun a server on one machine
iperf3 -c SERVER -t 10TCP throughput for 10 s from the clientN02
iperf3 -c SERVER -RReverse: server sends to client (test the other direction)

The "Retr" column counts TCP retransmissions and "Cwnd" shows the congestion window per interval. Throughput is bounded by the bottleneck link, and by cwnd/RTT: on a long RTT path the window, not the link, may be the limit.

13Review

You want to see the TCP handshake of your browser. Which tool and filter?

Wireshark with tcp.flags.syn == 1 (or tcpdump with 'tcp[tcpflags] & tcp-syn != 0').

Which command shows the iterative DNS resolution path?

dig +trace name.

How do you see TCP's cwnd and RTT estimate for a live connection on Linux?

ss -ti

traceroute shows "* * *" at hop 3 but later hops answer. Is hop 3 broken?

No: it just does not send ICMP Time Exceeded (or rate-limits it). Packets clearly pass through it.
