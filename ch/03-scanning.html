Chapter 03

Scanning

How an attacker maps a network: who is alive (ping sweep, ARP), which ports are open (connect, SYN, FIN, Xmas, Null, UDP, idle), how to stay anonymous, and how to identify the OS actively and passively. And the other side: detecting and blocking scans (Snort, ACLs, reducing attack surface). Every scan is explained by the exact packets it sends and the RFC rule it relies on.

1Scan goals and a TCP flags reminder

Map

Live IP addresses, subnets and masks.

Identify

Network devices, operating systems, applications and services, patch level.

Why flags are the scanner's main tool

A TCP stack must answer certain flag combinations in fixed ways (RFC 793). A scanner sends a combination and reads the answer: the reply flags tell open from closed, and the absence of a reply reveals a firewall. Chapter 00 has the full TCP header.

2Ports and port states

A port is the abstraction of "OS + service": a 16-bit number in the TCP and UDP header. TCP and UDP port spaces are separate, but the same number is customary for both (80/tcp and 80/udp for www).

RangeNameExamples
0–1023System / well-knownftp 21, ssh 22, telnet 23, smtp 25, time 37, dns 53, http 80, https 443

Open

A process listens. A SYN to an open port is the first packet of a handshake and gets SYN/ACK.

Closed

Nothing listens. The OS answers a SYN with RST/ACK.

Filtered

A packet filter (firewall) sits in front. No answer, or ICMP unreachable (Type 3 Code 13).

Vertical scan

One host, many ports. nmap 10.1.1.10 -p 1024-4423. "What runs on this server?"

Horizontal scan

One port, many hosts. nmap 10.1.1.0/24 -p 80. "Who on the network runs service X?" That is how worms spread.

3Who is alive: ping sweep and ARP scan

When ICMP is blocked

# ping 192.168.0.2
Request timeout for icmp_seq 0            ← looks "dead"
# hping2 192.168.0.2 -S -p 80
60 bytes from 192.168.0.2: flags=SA ...    ← SYN/ACK, it is alive!

Blocking ICMP does not hide a host that runs a service. Send a SYN to a common port (80, 443); any answer, even RST, proves it exists. nmap's default discovery for non-local targets sends ICMP echo, a SYN to 443, an ACK to 80 and an ICMP timestamp request.

ARP scan

Send an ARP Request ("who has 192.168.1.X?") for every address in the segment (nmap -sn -PR, arp-scan). Each probe is an Ethernet broadcast with EtherType 0x0806.

Advantage

Works at layer 2. A host firewall cannot hide the host: without answering ARP it cannot communicate at all.

Disadvantage

Works at layer 2. You must be on the same segment; ARP does not cross routers.

Timing math (lecture)

Class B = 65,536 hosts. One second per ping ≈ 18 hours. One port per host ≈ another 18 hours. Banners for 10 services per host (2 s each) ≈ 15 days. A class A (16 million) takes days.

How it is sped up

Discover hosts first, then scan ports only on live ones; pick relevant ports; split the work among many scanners (bots). Today Masscan and ZMap scan all of IPv4 on one port in under an hour, because they send asynchronously without waiting for replies (stateless scanning: they recognize replies by encoding a cookie in the source port / sequence number).

4ICMP-based attacks: Smurf, Fraggle, ping flood, Ping of Death

Smurf (1997, smurf.c)

ICMP Echo to a broadcast address with the victim's spoofed source IP. Every host replies to the victim and floods it. DDoS with amplification.

Fraggle

The same idea with UDP to port 7 (echo) and 19 (chargen) at a broadcast address. chargen answers with a stream of characters, so amplification is larger.

Ping flood

A huge number of pings (ping -f on Unix). The only requirement: more bandwidth than the victim.

Ping of Death

A malformed ping. IP is limited to 65,535 bytes; fragments that reassemble past the limit overflow a buffer and crash 1990s systems. Chapter 00 shows the offset math.

Defense

Do not forward directed broadcasts on routers (no ip directed-broadcast, default since 1999 after RFC 2644), disable echo/chargen, limit ICMP with ACLs to the DMZ and specific hosts, rate limiting. BCP 38 (ingress filtering) stops source-address spoofing.

Why FIN/Xmas/Null work

RFC 793: a segment without SYN, RST or ACK that arrives at a closed port is answered with RST; at an open port it is silently dropped. So no answer = open (or filtered!). Windows does not follow the RFC and always sends RST, so on Windows every port looks closed, which itself reveals the OS.

What nmap -sS really does, packet by packet
  1. Builds a raw IPv4 packet: random IP ID, TTL around 37–64, DF not set, source port fixed per scan (e.g. 54321).
  2. TCP: SYN, random Seq, window 1024, option MSS 1460 only (a recognizable nmap fingerprint).
  3. Sends to each port in a randomized order, adapting the rate to measured RTT and loss.
  4. SYN/ACK back → mark open; the kernel, which never opened this connection, would answer RST anyway, and nmap also sends RST itself.
  5. RST back → closed. Nothing after one retransmission, or ICMP 3/1,2,3,9,10,13 → filtered.

6Anonymous scanning

Silent scan

nmap -sT -T sneaky -p 80,135,139 ... slows down (a packet every ~15 s) to stay under the IDS threshold ("X packets in Y time").

Fragmentation scan

nmap -f ... splits the TCP header into tiny fragments. An IDS or firewall that does not reassemble cannot see the flags (see the animation).

Decoy scan

nmap -D 1.1.1.1,2.2.2.2,ME,3.3.3.3 ... sends spoofed copies of each probe from decoy addresses next to the real one. The target sees four scanners and cannot tell which is real.

Defense

Snort reassembles fragments in a preprocessor before inspection. Long time windows catch sneaky scans. Against decoys: spoofed packets often have a different TTL from the real one, and decoys that do not exist never answer the target's SYN/ACK with RST.

7Idle (zombie) scan: scanning without one packet from your address

Based on a predictable IP ID: older hosts increment the IP Identification field by 1 for every packet they send. If the zombie is idle, you can count how many packets it sent. nmap -sI <zombie> <target>

Why it works

The zombie is a counter the attacker can read remotely. The difference between 6 and 7 is exactly the RST the zombie sent on its own in response to the target's SYN/ACK. In step 1 the attacker probes several times to confirm the zombie really is idle (IPID rises by exactly 1).

Defense

Modern systems (Linux, Windows 8+) use random or per-destination IP IDs, so they cannot be zombies; old printers and IoT devices still can. Ingress filtering stops the spoofing, and a stateful firewall drops unsolicited SYN/ACKs.

8UDP scanning

nmap -sU sends an empty (0-byte) UDP datagram. ICMP Port Unreachable (Type 3, Code 3) = closed. Anything else = "open" (nmap marks it open|filtered).

The problems

If a firewall blocks the port there is no answer and the port looks open. Most OSes rate-limit ICMP unreachable messages (Linux: about one per second), so a full scan is very slow. nmap improves this with protocol-specific payloads (a DNS query to 53, SNMP to 161) that get a real answer from an open port.

9Detecting and preventing scans

Detecting scans gives early warning of an attack. The main tool is a NIDS such as Snort. Having the technology does not mean anyone watches in real time.

Snort: open-source IDS/IPS

Rule-based: signatures, protocol analysis and anomaly detection. Detects DoS, scans and intrusion attempts by monitoring traffic.

alert tcp any any -> $HOME_NET any (flags:F; msg:"FIN scan"; sid:1000001;)
alert tcp any any -> $HOME_NET any (flags:FPU; msg:"Xmas scan"; sid:1000002;)
alert tcp any any -> $HOME_NET any (flags:0; msg:"Null scan"; sid:1000003;)

Example rules for illustration (not from the slides). Each matches the exact flag byte the scan sends.

Prevention

  • Scanning is very hard to prevent; minimize exposure: disable every unneeded service (Unix: /etc/inetd.conf and startup scripts; Windows: Services).
  • Ping sweeps: decide which ICMP enters (e.g. only to the DMZ and specific hosts), ACLs by IP.
  • An IPS can detect and block, but it is expensive and has false positives.
Lecture question: design a mechanism that detects and blocks ping sweeps

Detect: one source sending Echo Requests to more than N different addresses in a time window (the lecture suggests "ECHO requests > ECHO replies within 15 s", i.e. many requests to addresses that do not answer). Legitimate? Management tools ping before connecting, so whitelist management servers, and check whether a connection actually follows the ping (management) or the source moves on to the next address (scan). Block: temporarily shun the source on the firewall or rate-limit its ICMP.

10OS fingerprinting

Why? Exploits target a specific OS and version. TCP/IP implementations differ in details the RFCs leave open, and those differences are a fingerprint.

Active · banner grabbing

Services announce themselves (HTTP Server:, SSH SSH-2.0-OpenSSH_7.4 Debian, FTP 220 ProFTPD). Easy, but can be faked.

Active · stack fingerprinting

nmap -O sends odd packets and compares replies to a database. Usually needs at least one open and one closed port; otherwise accuracy drops.

Passive · stack fingerprinting

Send nothing, just listen (central location or port mirror). Tools: Siphon, p0f. Needs access to the traffic.

Limitations

Applications that craft their own packets (nmap itself) look different from the OS. You must be where the traffic passes. And these parameters are easy to change, which also hurts active detection.

Detection and prevention

Active fingerprinting sends abnormal packets, so a NIDS catches it easily; it is not stealthy. You can change stack parameters (e.g. net.ipv4.ip_default_ttl), but that may hurt compatibility. Security through obscurity is not the first line: even if the attacker knows the OS, patching and hardening must stop them.
