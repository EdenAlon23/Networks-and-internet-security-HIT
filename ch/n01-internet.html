The Internet, its edge, its core and its layers

The first lecture builds the map that the whole course hangs on: what the Internet is made of, how bits get from one host to another through packet switching, how networks connect into one Internet, and how the work is split into layers. Every later chapter zooms into one part of this map.

1What is the Internet?

There are two equally valid answers, and exams ask for both.

The "nuts and bolts" view

Billions of connected computing devices called hosts or end systems (PCs, phones, servers, IoT), running network applications at the edge.

Packet switches that forward packets: routers (network layer) and link-layer switches.

Communication links: fiber, copper, radio, satellite. Each has a transmission rate called bandwidth (bits per second).

Networks: collections of devices, routers and links managed by one organization. The Internet is a "network of networks": interconnected ISPs.

The "services" view

The Internet is an infrastructure that provides services to applications: web, streaming, e-mail, games, e-commerce, social networks.

It gives applications a programming interface (sockets) with "hooks" that let a program on one host send data to a program on another, like a postal service with several delivery options (reliable TCP, fast best-effort UDP).

What is a protocol?

A protocol defines the format and the order of messages sent and received between network entities, and the actions taken when a message is sent or received (or when something does not arrive, like a timeout). Human analogy: "Hi" → "Hi" → "Got the time?" → "2:00". If the other side answers "Leave me alone", the protocol says what to do next.

Internet protocols are published as RFCs (Request for Comments) by the IETF (Internet Engineering Task Force). Examples: HTTP, TCP, IP, Ethernet, 802.11 (Wi-Fi), DNS, SMTP.

2The network edge: hosts and access networks

The edge is where the applications live: clients and servers (servers often sit in data centers). An access network connects an end system to its first router, the edge router.

When a host sends data, it breaks the application message into smaller chunks called packets of length L bits and transmits them into the access network at rate R. So the time to push one packet onto the link is the transmission delay L / R. This one formula comes back in almost every calculation question.

"Which access technologies share the medium between homes?" Cable and wireless do; DSL does not (each home has its own line to the central office). Shared media need a multiple-access protocol (chapter N10).

3Physical media

A bit propagates between a transmitter and receiver over a physical medium. Guided media keep the signal in a solid medium (copper, fiber, coax); unguided media let it propagate freely (radio).

4The network core: packet switching

The core is a mesh of interconnected routers. Hosts break messages into packets, and the network forwards packets from one router to the next along a path. Each packet is transmitted at the full link rate.

Store-and-forward

A router must receive the entire packet before it can start transmitting it on the outgoing link (it needs the whole packet to check it and read the header). So one packet of L bits over a path of N links of rate R (ignoring propagation and queues) takes d = N · L / R. With P packets sent back to back, the pipeline fills and the total is (N + P − 1) · L / R.

Store-and-forward over 3 links

Given

  • L = 10 kbit (1,250 bytes), R = 100 Mbps on every link, N = 3 links (2 routers), 1 packet

Solution

  1. One hop: L/R = 10,000 / 108 = 0.1 ms
  2. Three hops, store-and-forward: 3 × 0.1 = 0.3 ms
  3. If we send 5 packets back to back: (3 + 5 − 1) × 0.1 = 0.7 ms (not 5 × 0.3 = 1.5 ms, because the links work in parallel like a pipeline)

Queueing and loss

If packets arrive at a router faster than the outgoing link can transmit them for a while, they wait in the output buffer (queue): queueing delay. If the buffer is full, arriving packets are dropped (lost). Chapter N02 quantifies both.

Two key core functions

Forwarding (local)

Move an arriving packet from the router's input link to the right output link, using a forwarding table looked up by the destination address in the header. Happens in nanoseconds, in hardware.

Routing (global)

Determine the source-to-destination paths taken by packets, using routing algorithms that fill the forwarding tables. Happens in seconds, in software (chapter N09).

5Circuit switching vs packet switching

In circuit switching (the classic telephone network) resources along the path are reserved for the whole call: a dedicated share of every link. There is no sharing and no queueing, so performance is guaranteed, but a reserved circuit sits idle when the call is silent. The link is divided with FDM (each call gets a frequency band) or TDM (each call gets a periodic time slot and the full band during its slot).

Circuit setup time (classic exercise)

Given

  • File of 640,000 bits from A to B. All links 1.536 Mbps, TDM with 24 slots. Circuit setup takes 500 ms.

Solution

  1. Rate per circuit: 1.536 Mbps / 24 = 64 kbps
  2. Transmission: 640,000 / 64,000 = 10 s
  3. Total: 10 s + 0.5 s = 10.5 s

Why packet switching wins for bursty data

The 1 Mbps / 35 users example

Given

  • Link of 1 Mbps. Each user needs 100 kbps when active, and is active 10% of the time.

Solution

  1. Circuit switching: reserve 100 kbps per user → only 10 users.
  2. Packet switching with 35 users: trouble only if more than 10 are active at once. The number active is Binomial(35, 0.1).
  3. P(X ≥ 11) = 1 − Σk=0..10 C(35,k)·0.1k·0.935−k ≈ 0.0004
  4. So packet switching serves 3.5× more users with almost the same quality. The price: no guarantees, and congestion is possible.

6A network of networks

Hosts connect to the Internet through access ISPs (residential, enterprise, university). Access ISPs must be interconnected so that any two hosts can talk. Connecting every access ISP to every other does not scale (O(N2) links), so the structure evolved into a hierarchy:

  • Global transit ISPs (tier-1, e.g. Level 3/Lumen, NTT, Sprint) at the top, connected to each other by peering (no money changes hands).
  • Regional ISPs buy transit from tier-1s; access ISPs buy from regional ones (customer pays provider).
  • IXPs (Internet Exchange Points): buildings where many ISPs connect and peer with each other.
  • Content provider networks (Google, Microsoft, Akamai, Netflix) run their own global networks and data centers, peer directly with access ISPs, and bypass tier-1s where they can. This is why most of your traffic never touches a tier-1 network.
  • A PoP (point of presence) is a group of a provider's routers where customers connect. Multi-homing: an ISP connects to two or more providers for redundancy.

7Protocol layers and service models

Networks are complex, so the work is split into layers. Each layer implements a service using its own internal actions and relying on the service of the layer below. The benefit is modularity: you can change how one layer works (e.g. Wi-Fi instead of Ethernet) without touching the others. The airline analogy: ticket → baggage → gates → runway → routing, and the same in reverse on arrival.

The ISO/OSI model has 7 layers: it adds Presentation (encryption, compression, data format) and Session (synchronization, checkpointing, recovery) between transport and application. The Internet stack leaves those jobs to the application if it needs them.

Exam trap

"Which devices implement which layers?" Routers implement layers 1–3, link-layer switches 1–2, hosts all 5. That is why a router can never "see" your TCP port without breaking the layering rule (NAT and firewalls break it on purpose).

8Encapsulation

On the way down, each layer takes the unit from above as its payload and adds its own header: message M → segment HtM → datagram HnHtM → frame HlHnHtM. On the way up, each layer reads and removes its own header (decapsulation). A switch only opens up to the link header; a router opens up to the network header, then builds a fresh link header for the next link.

Application   M                                 message
Transport     [Ht | M]                          segment
Network       [Hn | Ht | M]                     datagram
Link          [Hl | Hn | Ht | M | trailer]      frame
Physical      0110 1010 0001 ...                bits
Why

Why not one big header? Because each header is read by a different device at a different scope: the link header by the next hop only, the network header by every router, the transport header only by the destination host. Keeping them separate is what lets each layer change independently.

Header overhead matters in calculations: with 20 B TCP + 20 B IP + 18 B Ethernet (14 header + 4 FCS), a 1,460-byte payload travels in a 1,518-byte frame, so the efficiency is 1460 / 1518 ≈ 96%. A 1-byte keystroke in telnet travels in a 59-byte frame or more (64 B minimum with padding).

10Review

What two things does a protocol define?

The format and order of messages, and the actions taken on sending, receiving, or on events like timeouts.

Why does store-and-forward add L/R per hop?

Each router must receive the whole packet before it starts sending it on, so every link adds one full transmission time.

Forwarding vs routing?

Forwarding is the local per-packet move from input to output link using the table; routing is the global computation of paths that fills the tables.

Which layers does a router implement?

Physical, link and network (1–3).

Name the 2 extra OSI layers and their job.

Presentation (encryption, compression, format) and Session (synchronization, checkpointing, recovery).

Why can packet switching support more users than circuit switching?

Users are bursty; statistical multiplexing shares capacity on demand, and the probability that too many are active at once is tiny.
