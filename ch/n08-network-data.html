Network layer: the data plane

The network layer moves datagrams from the sending host to the receiving host, and it is the first layer that runs in every router. This chapter covers the data plane, the per-router forwarding work: what is inside a router, longest-prefix matching, the IPv4 header and fragmentation, addressing and subnetting with CIDR, DHCP, NAT, IPv6, and generalized forwarding in SDN.

1Data plane and control plane

Data plane

Local, per-router function: determines how a datagram arriving on a router input port is forwarded to a router output port (forwarding). Nanoseconds, in hardware.

Control plane

Network-wide logic: determines how a datagram is routed along the end-to-end path from source to destination (routing). Two approaches: traditional routing algorithms implemented in every router, and software-defined networking (SDN) implemented in remote servers. Chapter N09.

The Internet's network-layer service model is best effort: no guarantee of successful delivery, of timing or order of delivery, or of bandwidth available to the flow. Other architectures (ATM, IntServ) offered guarantees, but best effort won: simple mechanisms enabled wide deployment, enough bandwidth provisioning makes real-time apps "good enough most of the time", and CDNs and application-layer replication bring services close to users.

2Router architecture

A router has input ports, a switching fabric, output ports, and a routing processor (control plane, software, millisecond time frame). The forwarding data plane is hardware working in nanoseconds.

Head-of-the-line (HOL) blocking at the input ports: if the fabric is slower than the input ports combined, queueing occurs at the inputs. A queued datagram at the front of the queue blocks the ones behind it, even if their output port is free. This is different from HTTP HOL blocking (N03), but it is the same idea.

3Longest prefix matching

A forwarding table cannot list 4 billion addresses one by one, so it lists address ranges (prefixes). When looking for the forwarding table entry for a destination address, use the longest address prefix that matches the destination. In hardware this is done in one clock cycle with TCAMs (ternary content addressable memories) that compare all entries in parallel, around 1M entries.

4Buffering and packet scheduling

How much buffering? RFC 3439 rule of thumb: average buffering equal to a "typical" RTT (say 250 ms) times link capacity C; e.g. C = 10 Gbps → 2.5 Gbit of buffer. More recent recommendation: with N flows, RTT · C / √N. Too much buffering increases delay (bufferbloat), especially for home routers; TCP needs a "just full enough" buffer.

6Fragmentation and reassembly

Network links have an MTU (max transfer unit), the largest link-level frame payload; different link types have different MTUs (Ethernet: 1,500 bytes). A large IP datagram is divided ("fragmented") within the network: one datagram becomes several, and they are reassembled only at the final destination. The IP header bits are used to identify and order related fragments.

4,000-byte datagram, MTU = 1,500

Given

  • Total length 4,000 = 20 header + 3,980 data. ID = x. MTU 1,500 → each fragment carries at most 1,480 data bytes (a multiple of 8).

Solution

  1. Fragment 1: length 1,500, ID x, MF = 1, offset 0
  2. Fragment 2: length 1,500, ID x, MF = 1, offset 1480/8 = 185
  3. Fragment 3: data 3,980 − 2,960 = 1,020 → length 1,040, ID x, MF = 0 (last), offset 2960/8 = 370
  4. Check: 1,480 + 1,480 + 1,020 = 3,980 ✓. Each fragment has its own 20-byte header, so 3 headers travel instead of one.
Remember

Offset is in 8-byte units because it has 13 bits but the total length has 16. The data size of every fragment except the last must therefore be a multiple of 8. If any fragment is lost, the whole datagram is lost (no partial reassembly). The DF flag forbids fragmentation: a router then drops and sends ICMP "fragmentation needed", which is how path-MTU discovery works. IPv6 routers never fragment.

Fragment-based attacks (Teardrop, Ping of Death, fragmentation scans) are in the security course: chapter 05 and chapter 03.

7IP addressing and CIDR

An IP address is a 32-bit identifier associated with each host or router interface (the connection between a host/router and a physical link). Routers typically have multiple interfaces; a host usually has one or two (wired Ethernet, wireless 802.11). Dotted-decimal notation: 223.1.1.1 = 11011111 00000001 00000001 00000001.

A subnet is a set of device interfaces that can physically reach each other without passing through an intervening router. All interfaces in a subnet share the high-order bits (the subnet part); the low-order bits are the host part. Recipe: detach each interface from its host or router, creating "islands" of isolated networks; each island is a subnet. Note that each point-to-point link between two routers is its own subnet.

CIDR (Classless InterDomain Routing): the subnet portion has arbitrary length. Format a.b.c.d/x, where x is the number of bits in the subnet portion. Example: 200.23.16.0/23 = 11001000 00010111 00010000 00000000 → 23 network bits, 9 host bits → 29 = 512 addresses (510 usable: the all-zeros host part is the network address and the all-ones is the broadcast address).

8Subnetting step by step

Network address, broadcast and host range

Given

  • Host 172.16.45.200/20

Solution

  1. /20 → mask 255.255.240.0. The interesting octet is the 3rd: 45 = 0010 1101; keep the top 4 bits → 0010 0000 = 32
  2. Network address: 172.16.32.0; block size in the 3rd octet: 256 − 240 = 16 → the next network is 172.16.48.0
  3. Broadcast: 172.16.47.255; hosts 172.16.32.1 – 172.16.47.254 (4,094 hosts)

Splitting a /24 for three departments (VLSM)

Given

  • Block 223.1.17.0/24. Subnet 1 needs 90 interfaces, subnet 2 needs 60, subnet 3 needs 12.

Solution

  1. Allocate the biggest first. 90 → need 128 addresses → /25: 223.1.17.0/25 (.0–.127)
  2. 60 → need 64 → /26: 223.1.17.128/26 (.128–.191)
  3. 12 → need 16 → /28: 223.1.17.192/28 (.192–.207). The rest (.208–.255) stays free.
  4. Each block must start at a multiple of its own size, so allocating largest-first avoids gaps.
Exam trap

Remember to count the network and broadcast addresses (and, if the question says so, the router's interface) when deciding a block size: 62 hosts fit in /26 (64 − 2), but 63 do not.

9DHCP: Dynamic Host Configuration Protocol

How does a host get an IP address? Either hard-coded by the sysadmin in a config file, or dynamically from a server with DHCP: "plug-and-play". Goals: renew the lease on an address in use, reuse addresses (an address is held only while connected), and support mobile users who join and leave. DHCP runs over UDP, server port 67, client port 68.

DORA
  1. Discover (optional broadcast): src 0.0.0.0:68 → dst 255.255.255.255:67, yiaddr 0.0.0.0, transaction ID 654. "Is there a DHCP server out there?"
  2. Offer: src 223.1.2.5:67 → dst 255.255.255.255:68, yiaddr 223.1.2.4, transaction ID 654, lifetime 3600 s. "I'm a DHCP server! Here's an IP address you can use."
  3. Request (broadcast, so other offering servers know they were not chosen): yiaddr 223.1.2.4, transaction ID 655. "I'll take that IP address!"
  4. ACK: yiaddr 223.1.2.4, transaction ID 655, lifetime 3600 s. "OK. You have the IP address."

DHCP returns more than an IP address: the address of the first-hop router (default gateway), the name and IP of the DNS server, and the network mask (which part is network and which is host). The DHCP server is often co-located in the home or campus router. Rogue DHCP servers and DHCP starvation are covered in security chapter 04.

10How networks get address blocks; route aggregation

A network gets an allocated portion of its provider ISP's address space. Example: the ISP has 200.23.16.0/20 and splits it into 8 blocks of /23: organization 0 gets 200.23.16.0/23, organization 1 gets 200.23.18.0/23, … organization 7 gets 200.23.30.0/23.

Hierarchical addressing allows efficient advertisement of routing information: the ISP tells the rest of the Internet only "send me anything with addresses beginning 200.23.16.0/20" (route aggregation). If organization 1 moves to another ISP, that ISP advertises the more specific route 200.23.18.0/23; longest prefix matching makes it win over the aggregate.

Who gives ISPs their blocks? ICANN allocates to the 5 regional registries (RIRs: ARIN, RIPE NCC (Europe and Israel), APNIC, LACNIC, AfriNIC), which allocate to ISPs. The last IPv4 chunk was allocated in 2011; NAT and IPv6 are the answers to exhaustion.

11NAT: Network Address Translation

All devices in a local network share just one IPv4 address as far as the outside world is concerned. Inside they use private addresses (e.g. 10.0.0.0/24); every datagram leaving the network has the same source IP (e.g. 138.76.29.7) and a different source port.

Translation step by step
  1. Host 10.0.0.1 sends a datagram to 128.119.40.186:80 from source 10.0.0.1:3345.
  2. The NAT router changes the source address to 138.76.29.7:5001 and adds an entry to the NAT translation table: 138.76.29.7, 5001 ↔ 10.0.0.1, 3345.
  3. The reply arrives addressed to 138.76.29.7:5001.
  4. The router looks up the table and changes the destination to 10.0.0.1:3345, then forwards it inside.
  • Advantages: one IP from the ISP for all devices; local addresses can change without notifying the world; the ISP can change without changing local addresses; inside devices are not directly addressable from outside (a side benefit, not real security).
  • The 16-bit port field allows about 60,000 simultaneous connections with one LAN-side address.
  • Controversies: routers "should" only process up to layer 3, but NAT rewrites ports (layer 4); the address shortage "should" be solved by IPv6; it violates the end-to-end argument; NAT traversal: what if a client outside wants to connect to a server behind NAT? (static port forwarding, UPnP, relaying like STUN/TURN). Yet NAT is everywhere: home routers, institutional nets, 4G/5G cellular (carrier-grade NAT).

The exact header fields NAT rewrites (and the checksums) are in security chapter 09.

12IPv6

Initial motivation: the 32-bit IPv4 address space would be completely allocated. Additional motivation: speed up processing and forwarding with a 40-byte fixed-length header, and enable different network-layer treatment of "flows". IPv6 addresses are 128 bits, written in hex groups: 2001:db8:0:0:8:800:200c:417a = 2001:db8::8:800:200c:417a.

13Generalized forwarding and SDN

Each router contains a flow table computed and distributed by a logically centralized controller. Generalized forwarding is "match plus action": match bits in arriving packet headers, in any layer, and take an action: drop, forward (to a port), modify fields, or send to the controller. Each rule also has a priority (to disambiguate overlapping patterns) and counters (#bytes and #packets).

So one abstraction unifies router, switch, firewall and NAT. Middleboxes (NAT, firewalls, IDS, load balancers, caches) used to be separate proprietary boxes; network functions virtualization (NFV) runs them as software on commodity hardware, programmed with SDN.

14Review

Forwarding table has 10.0.0.0/8 → A and 10.1.0.0/16 → B. Where does 10.1.2.3 go?

B: both match, the /16 is longer.

A 2,400-byte datagram (20 B header) crosses a link with MTU 1,000. Fragments?

Data 2,380; max data per fragment 976 (multiple of 8 ≤ 980). Fragments: 976 (offset 0, MF=1), 976 (offset 122, MF=1), 428 (offset 244, MF=0); lengths 996, 996, 448.

How many usable hosts in 192.168.10.64/27, and what is its broadcast address?

32 − 2 = 30 hosts (.65–.94); broadcast 192.168.10.95.

Besides an IP address, what does DHCP provide?

Default gateway, DNS server, subnet mask, and the lease time.

Name three IPv4 header features IPv6 removed.

The header checksum, fragmentation at routers, and variable-length options.
